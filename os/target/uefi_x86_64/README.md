# UEFI x86-64

Saltic на ноутбуке без Linux: программа собирается как UEFI-приложение
(PE32+) и грузится прошивкой с флешки.

| Файл | Что делает |
|---|---|
| `hello.saltic` | первая программа: текст на экране и одно нажатие |
| `firmware.saltic` | общая основа: физические адреса, чтение и запись памяти, таблицы UEFI и ACPI, ECAM, поиск устройства PCI |
| `pci.saltic` | перечисление устройств PCI: системная таблица UEFI → ACPI RSDP → XSDT → MCFG → ECAM, обход всех шин; не выходит, пока ноутбук не выключат |
| `rtl8111.saltic` | драйвер Ethernet Realtek RTL8111: найти карту, сбросить, кольца дескрипторов в арене, дождаться линка; `send` кадра, `received`/`read_frame`/`release` для приёма. QEMU эту карту не эмулирует — проверка только на железе |
| `net.saltic` | сеть на группах байтов: Ethernet, ARP (ответ «10.0.0.2 — это я»), IPv4 с контрольной суммой, UDP; проверяется на Linux |
| `agent.saltic` | приёмник команд на 10.0.0.2:5555: `help`, `info`, `pci`, `mem <адрес> [байт]`, `echo`, `upload <байт>`, `check`, `run`; отвечает на ARP и по-русски (экран Acer — по-английски: у прошивки нет кириллицы); куски программы принимает на порт 5556 в арену и запускает её через прошивку |
| `uefi.saltic` | таблицы прошивки на Saltic через `firmware.call`: консоль (`wide_console` — самый большой текстовый режим), загрузка и запуск образа (`start_image`) |
| `graphics.saltic` | графика прошивки (GOP): найти протокол, размер экрана, формат пикселя, длина строки, адрес кадрового буфера; `fill` — прямоугольник прямо в видеопамять |
| `visitor.saltic` | маленькая программа для проверки `upload`: печатает приветствие и возвращается к агенту |
| `tools/listen.py` | «ухо» на проводе: печатает все кадры на интерфейсе (`sudo python3 tools/listen.py eno1`) |
| `tools/talk.py` | сырой разговор без ARP: раз в секунду шлёт `ping N` и печатает ответы (`sudo python3 tools/talk.py eno1`) |
| `tools/say.py` | одна команда агенту без root: `python3 tools/say.py info` (нужен адрес 10.0.0.1 на `eno1`) |
| `tools/upload.py` | залить программу агенту и, с `--run`, запустить: `python3 tools/upload.py visitor.efi --run`; куски по 1024 байта с подтверждением, сверка суммы |
| `build.sh` | собирает `EFI/BOOT/BOOTX64.EFI` и папку образа флешки |
| `run.sh` | запускает собранное в QEMU x86-64 с прошивкой OVMF; `--check` — без окна, жмёт клавишу и ждёт «Bye!» (так его зовёт `tests/run.sh uefi`) |

Цель компилятора — `x86_64-uefi`. Образ — одна секция PE32+: таблица
переходов, регистры, переведённый код, точка входа и память гостя.
Системные вызовы идут в прошивку: вывод — `ConOut->OutputString`,
клавиша — `ConIn->ReadKeyStroke`, выход — возврат в прошивку.

## Флешка

1. Собрать: `bash os/target/uefi_x86_64/build.sh` — папка образа
   `.cache/build/uefi_x86_64/image`.
2. Проверить в QEMU: `bash os/target/uefi_x86_64/run.sh`.
3. Флешку отформатировать в FAT32 (`sudo mkfs.vfat -F 32 /dev/sdX1`,
   где `sdX1` — раздел флешки, проверить по `lsblk`), смонтировать и
   скопировать туда папку `EFI` из образа:
   `sudo cp -r .cache/build/uefi_x86_64/image/EFI /mnt/`.
4. На ноутбуке: Secure Boot выключен, загрузка с USB в режиме UEFI.
   Прошивка сама найдёт `EFI/BOOT/BOOTX64.EFI`.

## Сведения о прошивке

`core.cpu.firmware(кусок)` — системный вызов 500 в прослойке UEFI. Кусок 0–3 —
16-битные части базы гостевой памяти (`r14`: гостевой адрес `x` — это
физический `r14 + x`), 4–7 — части указателя на системную таблицу UEFI.
Прошивка держит память один к одному, поэтому физический адрес `P` ниже
4 ГБ читается как гостевой `P − r14` (так `pci.saltic` доходит до ECAM).

## На ноутбуке через Ventoy

Ventoy показывает и `.efi`, и `.iso`, если ноутбук загружен в UEFI. Enter,
которым выбирают пункт меню, остаётся в буфере клавиатуры: программа с
«Press any key» сразу выходит, и прошивка грузит следующее по списку. Ждать
конкретную клавишу или не выходить вовсе.

Первый запуск — 01.11.2026, Acer Aspire E5-575G (Kaby Lake): `pci.saltic`
нашла 19 устройств, среди них Ethernet Realtek RTL8111 (`10ec:8168`) и Wi-Fi
Qualcomm Atheros QCA9377 (`168c:0042`).

Вечером 01.11.2026 `rtl8111.saltic` отправила по кабелю (Acer ↔ второй
ноутбук напрямую, линк 1000 Mbit/s) десять UDP-рассылок, все дошли.
Физический адрес арены надо выравнивать на 256 при запуске: прошивка Acer
кладёт программу по неровному адресу, а кольцу дескрипторов нужно
выравнивание на 256, иначе карта не берёт пакет.

Там же, через 7 минут: драйвер принял `ping N` от `tools/talk.py` и на каждый
ответил `echo: ping N` в ту же секунду — первый приёмник команд на Saltic.
Сеть — два ноутбука, соединённых кабелем напрямую; на втором `eno1` без
IP-адреса, поэтому оба скрипта работают через сырой сокет и `sudo`.

Агент, 01.11.2026: на `eno1` профиль NetworkManager `saltic-wire` с адресом
10.0.0.1/24 (`nmcli connection add type ethernet ifname eno1 con-name
saltic-wire ipv4.method manual ipv4.addresses 10.0.0.1/24 ipv6.method
link-local connection.autoconnect-priority 10`). Linux находит Acer по ARP,
`tools/say.py` отвечают `help`, `info`, `pci` (19 устройств текстом) и `mem`
(сырая память железа — конфигурация PCI и регистры карты).

`upload`, 01.11.2026: `cpu.start_image(hi, lo, размер)` — системный вызов 501:
прослойка зовёт `LoadImage` и `StartImage` прошивки на образе из памяти.
Дочерняя программа возвращается к агенту (`visitor` — статус 0). Новая версия
самого агента не возвращается: она сбрасывает карту и слушает сама — так
агент обновился по сети за 1,6 секунды (452 КБ) и заговорил по-русски.

Экран, 01.11.2026: `cpu.wide_console()` — системный вызов 502: перебрать
текстовые режимы консоли прошивки (`QueryMode`), включить самый большой
(`SetMode`), вернуть столбцы × строки. На Acer — 170 × 40 вместо 80 × 25.
Новый агент доехал до ноутбука по сети за 1,6 секунды, без флешки.

`firmware.call`, 01.11.2026: один общий вызов прошивки вместо частных.
`core.cpu.call(hi, lo)` — системный вызов 503: блок в арене (адрес функции,
до 10 аргументов по 8 байт, результат); прослойка раскладывает первые четыре
по `rcx`, `rdx`, `r8`, `r9`, остальные — на выровненный стек. Частные вызовы
501 (`start_image`) и 502 (`wide_console`) ушли из компилятора — теперь это
Saltic в `uefi.saltic`. Команда агента `screen` нарисовала на Acer первые
пиксели: экран 1366 × 768, BGR, строка 1376 пикселей, кадр по адресу
`c0000000`.
