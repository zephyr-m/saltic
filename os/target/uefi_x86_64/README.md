# UEFI x86-64

Saltic на ноутбуке без Linux: программа собирается как UEFI-приложение
(PE32+) и грузится прошивкой с флешки.

| Файл | Что делает |
|---|---|
| `hello.saltic` | первая программа: текст на экране и одно нажатие |
| `firmware.saltic` | общая основа: физические адреса, чтение и запись памяти, таблицы UEFI и ACPI, ECAM, поиск устройства PCI |
| `pci.saltic` | перечисление устройств PCI: системная таблица UEFI → ACPI RSDP → XSDT → MCFG → ECAM, обход всех шин; не выходит, пока ноутбук не выключат |
| `rtl8111.saltic` | драйвер Ethernet Realtek RTL8111: найти карту, сбросить, кольца дескрипторов в арене, дождаться линка, объявить себя рассылкой, затем вечно слушать: печатать принятые кадры и отвечать `echo: <текст>` на UDP-команды порта 5555. QEMU эту карту не эмулирует — проверка только на железе |
| `tools/listen.py` | «ухо» на проводе: печатает все кадры на интерфейсе (`sudo python3 tools/listen.py eno1`) |
| `tools/talk.py` | разговор с драйвером: раз в секунду шлёт `ping N` (10.0.0.1:5556 → 10.0.0.2:5555) и печатает ответы (`sudo python3 tools/talk.py eno1`) |
| `build.sh` | собирает `EFI/BOOT/BOOTX64.EFI` и папку образа флешки |
| `run.sh` | запускает собранное в QEMU x86-64 с прошивкой OVMF; `--check` — без окна, жмёт клавишу и ждёт «Bye!» (так его зовёт `tests/run.sh uefi`) |

Цель компилятора — `x86_64-uefi`. Образ — одна секция PE32+: таблица
переходов, регистры, переведённый код, точка входа и память гостя.
Системные вызовы идут в прошивку: вывод — `ConOut->OutputString`,
клавиша — `ConIn->ReadKeyStroke`, выход — возврат в прошивку.

## Флешка

1. Собрать: `bash os/target/uefi_x86_64/build.sh` — папка образа
   `.cache/build/uefi_x86_64/image`.
2. Проверить в QEMU: `bash os/target/uefi_x86_64/run.sh`.
3. Флешку отформатировать в FAT32 (`sudo mkfs.vfat -F 32 /dev/sdX1`,
   где `sdX1` — раздел флешки, проверить по `lsblk`), смонтировать и
   скопировать туда папку `EFI` из образа:
   `sudo cp -r .cache/build/uefi_x86_64/image/EFI /mnt/`.
4. На ноутбуке: Secure Boot выключен, загрузка с USB в режиме UEFI.
   Прошивка сама найдёт `EFI/BOOT/BOOTX64.EFI`.

## Сведения о прошивке

`core.cpu.firmware(кусок)` — системный вызов 500 в прослойке UEFI. Кусок 0–3 —
16-битные части базы гостевой памяти (`r14`: гостевой адрес `x` — это
физический `r14 + x`), 4–7 — части указателя на системную таблицу UEFI.
Прошивка держит память один к одному, поэтому физический адрес `P` ниже
4 ГБ читается как гостевой `P − r14` (так `pci.saltic` доходит до ECAM).

## На ноутбуке через Ventoy

Ventoy показывает и `.efi`, и `.iso`, если ноутбук загружен в UEFI. Enter,
которым выбирают пункт меню, остаётся в буфере клавиатуры: программа с
«Press any key» сразу выходит, и прошивка грузит следующее по списку. Ждать
конкретную клавишу или не выходить вовсе.

Первый запуск — 01.11.2026, Acer Aspire E5-575G (Kaby Lake): `pci.saltic`
нашла 19 устройств, среди них Ethernet Realtek RTL8111 (`10ec:8168`) и Wi-Fi
Qualcomm Atheros QCA9377 (`168c:0042`).

Вечером 01.11.2026 `rtl8111.saltic` отправила по кабелю (Acer ↔ второй
ноутбук напрямую, линк 1000 Mbit/s) десять UDP-рассылок, все дошли.
Физический адрес арены надо выравнивать на 256 при запуске: прошивка Acer
кладёт программу по неровному адресу, а кольцу дескрипторов нужно
выравнивание на 256, иначе карта не берёт пакет.

Там же, через 7 минут: драйвер принял `ping N` от `tools/talk.py` и на каждый
ответил `echo: ping N` в ту же секунду — первый приёмник команд на Saltic.
Сеть — два ноутбука, соединённых кабелем напрямую; на втором `eno1` без
IP-адреса, поэтому оба скрипта работают через сырой сокет и `sudo`.
