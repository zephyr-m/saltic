## 1. Договор: `compiler/backend.saltic`

Почему здесь и так: по канону `backend.saltic` — публичное лицо модуля
`backend/`, и именно он «объявляет публичные типы и операции» всех детей
(бэкендов). Имя `contract` занято (`intrinsic.contract` в `codegen`),
`machine` перегружено (`selfhost.machine.word`, `compiler.machine`). Алиас
`backend` свободен всюду. [чтение канона, grep]

Роль — число; регистр под неё выбирает исполнитель. Операция — метод
исполнителя `(compiler, …) -> compiler`, пишет в `compiler.machine`.

| Роль | RV32I | Смысл |
|---|---|---|
| `VALUE` (= `ARG0`) | a0 | результат навыка, первый аргумент |
| `ERROR` (= `ARG1`) | a1 | id ошибки, второй аргумент |
| `ARG2`…`ARG7` | a2…a7 | аргументы; `FIXED_SOURCE_KIND` = `ARG6`, `FIXED_TARGET_KIND` = `ARG7` |
| `SCRATCH0`…`SCRATCH4` | t0…t4 | временные codegen |
| `FRAME`, `STACK`, `RETURN` | s0, sp, ra | кадр, стек, адрес возврата |
| `HEAP_TOP`, `ESCAPE_BOTTOM` | s1, s2 | вершина кучи, низ таблицы побегов |
| `ARGV` | s3 | аргументы процесса |
| `REGION_MARK`, `ESCAPE_MARK` | s4, s5 | метки региона при входе в навык |

`argument(index)` → роль `ARG<index>`; секции — числа `CODE`, `RODATA`,
`DATA`, `BSS`. T6 (широкие смещения) ролью не стал — он внутреннее дело
исполнителя RV32I (`assembler.emit_op`), договор про него не знает.

Операции (43):

| Группа | Операции |
|---|---|
| Программа и данные (8) | `new_program(entry)`, `heap_size(bytes)`, `label(name)`, `data_label(section, name)`, `align(section, n)`, `data_word(section, word)`, `data_text(section, text)`, `reserve(bytes)` |
| Константы и адреса (3) | `load_immediate(to, n)`, `load_word(to, word)`, `load_address(to, label, addend)` |
| Регистры (12) | `move`, `add_immediate`, `add`, `sub`, `and_immediate`, `or_immediate`, `shift_left`, `shift_right_signed`, `shift_right_unsigned`, `set_less`, `set_zero`, `set_nonzero` |
| Проверенная арифметика (2) | `add_checked()`, `sub_checked()` — `VALUE = VALUE ± ERROR`, `ERROR` = `CALL_NO_ERROR` или `ERROR_NUMBER_OVERFLOW`; на x86 это `add; jo` |
| Память и стек (5) | `load(to, base, off)`, `store(from, base, off)`, `store_zero(base, off)`, `push(from)`, `pop(to)` |
| Близкие переходы (5) | `branch_equal`, `branch_not_equal`, `branch_greater_equal(l, r, label)`, `branch_zero`, `branch_not_negative(from, label)` |
| Дальние переходы (6) | `jump(label)`, `jump_if_equal`, `jump_if_not_equal(l, r, label)`, `jump_if_zero`, `jump_if_nonzero(from, label)`, `jump_far(label)` — через адрес в `SCRATCH1` |
| Вызовы (2) | `call(label)`, `ret()` |

Две оговорки, честно унаследованные от RV32I ради байт-в-байт:
«близкий» переход (B-команда, ±4 КБ) и «дальний» (обратная B + JAL) — на
x86 оба станут `jcc rel32`, разница исчезнет; `jump_far` — переход на любое
расстояние (в `_start` на `rt_missing_args`). Роли `ZERO` нет: вместо неё
`store_zero`, `branch_zero`, `jump_if_zero` и т. п. — у x86 и Thumb-2
нулевого регистра нет, явные операции дешевле. [предп.]

## 2. Исполнитель: `backend/rv32i.saltic`

`Executor` — Box с одним полем `far_calls` и 43 методами договора плюс
три внутренних (`register`, `section`, `checked`). Роль → регистр через
константу-группу `REGISTER_OF_ROLE` (порядок = номера ролей в `backend`).
Команды — через `assembler.emit_op` (тот же код, что был `state.emit_op`,
с разворотом широких смещений через T6), метки и данные — `machine.layout`.

```saltic
Executor = Box {
    far_calls = no

    skill register(role) {
        out group.get(REGISTER_OF_ROLE, role)
    }

    skill new_program(compiler, entry) {
        compiler.machine = layout.host(entry)
        compiler.machine.far_calls = far_calls
        out compiler
    }

    skill load(compiler, to, base, offset) {
        out assembler.emit_op(compiler, instruction.Kind.LW, register(to), register(base), registers.ZERO, offset)
    }

    skill jump_if_zero(compiler, from, name) {
        compiler.machine = layout.emit(compiler.machine, instruction.Kind.BNE, registers.ZERO, register(from), registers.ZERO, SKIP_NEXT)
        out jump(compiler, name)
    }
}
```

Как его зовёт кодоген: `State` получил поле `executor`; `compiler.saltic`
создаёт `state.State { …, executor = rv32i.Executor { far_calls = far_calls } }`;
каждый навык кодогена берёт `@executor = compiler.executor` и пишет
`compiler = executor.load(compiler, backend.VALUE, backend.FRAME, slot)`.
Тип `executor` чекеру неизвестен → вызов идёт через диспетчер
`rt_method_load` (`functions.compile_dispatch`): проверка тега Box, номер
типа в последнем поле, переход на `saltic_Executor.load`. Когда появится
`x86_64_native.Executor`, тот же диспетчер выберет его. [чтение, запуск]

Фасад `rv32i.saltic` (`operation`, `emit`, `branch`, …) оставлен как был —
его берут `os/target/qemu_virt/platform` и `tests/machine*`.

## 3. Что язык дал и чего не дал (всё — в рамках нынешнего языка)

1. **Поле «любой Box».** Тип поля — тип его значения по умолчанию, и чекер
   отказывает: `executor = []` → «нельзя присвоить Box Executor полю типа
   группа»; `none`, `0`, `Other {}` — то же [запуск, проба]. Рабочая форма:
   `executor = backend.unassigned()` — значение по умолчанию через навык,
   тип результата навыка чекеру неизвестен → присвоить можно любой Box.
   `unassigned()` отдаёт `none`. Это не обход, а свойство языка (типы
   выводятся, где известны), но стоит записать как форму «поле без типа».
2. **`program` — ключевое слово**, методом быть не может → `new_program`.
3. **Имена вариантов enum глобальны**: `backend.Section { CODE, … }`
   столкнулся с `layout.Section` («вариант 'CODE' уже принадлежит другому
   enum»). Секции в договоре — числовые константы `backend.CODE` и т. д.
4. **self и поля.** Присваивать поля self внутри метода не нужно:
   метод берёт `compiler` параметром и пишет `compiler.machine = …` —
   это уже принято во всём кодогене. Поле self читается голым именем
   (`far_calls`), соседний метод зовётся голым именем (`jump(compiler, name)`,
   `register(to)`) и имеет приоритет над одноимённым навыком модуля
   (`rv32i.jump`, `rv32i.label` фасада) [запуск, проба и самосборка].
5. Числа — литеральные константы (`backend.VALUE = 0`) подставляются в код
   без вызова; группа `REGISTER_OF_ROLE` — через ленивый геттер.

## 4. Новый ребёнок `backend/rv32i/assembler.saltic` (на решение автора)

иначе (например, внутрь `rv32i.saltic`), перенос механический.

## 10. Что осталось и решения для автора

Остатки в кодогене:

- `state.saltic:78` — `machine = layout.Program {}`: значение поля по
  умолчанию, единственная нить к `backend/rv32i/machine`. Её держат 65
  `state.State {}` в `tests/machine/translation/*` (рантайм пишет в
  `compiler.machine` напрямую). Решение: `Program` (секции, метки, данные)
  становится общим типом в `backend/` с патчами исполнителя — тогда нить
  уходит сама; либо `machine = backend.unassigned()` и 65 правок в тестах.
- `rv32i.saltic` — больше 12 публичных операций (Executor + 16 навыков
  фасада). Фасад нужен `qemu_virt/platform` и `tests/machine`; можно
  опустить его в `rv32i/facade.saltic` или оставить как есть.
- `abi/call.saltic` — номера регистров RV32I (`argument_register`,
  `FIXED_*_REGISTER`) стали мёртвыми вне `tests/abi`; можно убрать или
  заменить ролями договора.

Шаг 3 — рантайм (2 846 строк, 1 357 `emit_op`, 42 вида команд, 24 роли):

- **(б) рантайм на договоре.** Договор дорастёт примерно до 60 операций:
  байтовые и полусловные `load8/16`, `store8/16`, беззнаковые
  `set_less_unsigned` / `branch_less_unsigned` / `branch_unsigned_greater`,
  `xor`, `and`/`or` регистровые, сдвиги регистром, `syscall(имя)` вместо
  `ECALL` с номером, `wait`, `fence`, `csr_*` (qemu_virt), `absolute_address`
  и `append_label_address` (таблицы). Роли: ещё `SCRATCH5`, `SCRATCH6`
  (t5, t6 — T6 как значение в 40 местах, аудит 10.4); `ARG4`, `ARG5` уже
  есть. Замена механическая, байты те же — проверка как здесь. Скрытые
  контракты T2 (`rt_box_set` → `rt_region_barrier`), провалы меток
  (`rt_string_upper` → `rt_string_case`, `rt_fixed_mem_load32` →
  `rt_fixed_mem_load`) и кросс-файловые метки `.L_equal_yes` при этом надо
  либо закрепить явно (роль `BARRIER_BOX`, явный `jump`), либо оставить —
  на договоре они видны, но всё ещё держатся на порядке эмиссии.
- **(в) рантайм на Saltic.** Нужны фиксированные типы в параметрах и `out`
  и навыки без кадра региона (иначе `rt_alloc` зовёт пролог, зовущий
  `rt_alloc`) — новая возможность языка, решает автор.
- **Бюджет регистров** — решить до (б): 24 роли RV32I против 15 у x86-64 и
  13 у Thumb-2. Либо исполнитель x86 держит «регистровый файл» для холодных
  ролей (как перевод сейчас), либо рантайм ужимается до ~14 ролей один раз.
- Моё предложение [предп.]: (б) сейчас (один рантайм на все исполнители,
  ~1 700 строк 1:1, проверка байт в байт), (в) потом по одной процедуре.
  Решение о бюджете регистров — перед началом.
