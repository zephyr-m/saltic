## Коротко

- Сейчас: число — 29 бит + тег в 32-битном слове (`abi/value`: WORD_BITS = 32,
  `tags`: SHIFT = 3, все 8 тегов заняты); фиксированные `u8…usize` — сырые
  32 бита, тип из сигнатуры, вид в `a6/a7`, из навыка не выходят (4 запрета
  чекера: группа, аргумент, поле Box, `out`). [чтение, запуск: проба Б дала
  ровно 4 ошибки]
- Адреса на x86-64: `Phys { hi, lo }` по 16 бит в `firmware`, `[hi, lo]` в
  qemu_virt, 16-битные куски в `cpu.firmware(piece)`, `cpu.call(hi, lo)`,
  `mem.arena(piece)`. Строк с hi/lo в `os/` — **176 в 31 файле**; ещё 75
  обёрток `firmware.number(…)` и 66 литералов `Phys {`. [запуск: grep]
- Таблица вариантов — ниже. Мой ответ на развилку 0: **А**; варианты 1 и 3
  целиком живут внутри А, вариант 2 — это Б и отдельный проект.
- Рекомендация: **вариант 3 в два шага** — сначала выпустить нынешние
  фиксированные типы из навыка (решение автора 03.11 уже есть; hi/lo в ОС
  исчезают уже на этом шаге, адреса там и так ниже 4 ГБ), потом `u64/i64`
  как «широкое сырое значение в два слова». Вариант 2 — после договора машины
  и именованных смещений (аудит Б2.1), если автор решит поднимать канон до
  RV64.

skill guest(p, base) {
    @lo = p.lo - base.lo

## 5. Что сломается и чего не хватает каждому варианту

- **1.** Все 8 тегов заняты → `i64` живёт под тегом BOX с особым видом;
  `rt_add` в строке тега не смотрит (`emit_checked_word`) → либо вывод типов
  через навыки (та же работа, что в 3), либо проверка тега в каждом сложении.
  `==` на двух `i64` — равенство по ссылке (PLAN, «равенство групп»).
  Выделение на каждой операции — для CH32V003 (2 КБ) непригодно. Вариант 1
  = вариант 3 по чекеру + новый вид объекта + рантайм; выигрывает только
  записью `p + 8` без `u32.from`. [чтение, предп.]
- **2.** Ломает всё сразу и сцепляет задачу 2 с Б. Полка: новый RV64-бинарник
  нельзя собрать нынешним компилятором без промежуточного «RV32I-компилятор,
  выдающий RV64» — два шага полки. Эталоны `tests/machine/*` (golden, patches,
  immediate, translation) — все переписать. `number_is_wide` и `word` (Box из
  4 байтов) — переделать. Для малых плат — эмуляция или два мира. Это
  «Saltic-64», а не «64-битные числа». [чтение, предп.]
- **3.** Скрытая цена — сборщик: сырое слово в поле Box/элементе группы
  неотличимо от указателя по тегу (`emit_pointer_address`); нужен признак
  «сырой слот» (бит в `BOX_FIELD_ID`, флаг в заголовке группы `group:u32`) и
  его учёт в `rt_box_get/set`, обходах `emit_visit`/`emit_escape_walk`,
  `rt_region_barrier`. Вторая цена — вывод типов параметров (решение автора
  03.11; пометка автора о сложности справедлива). Третья — церемония
  `u32.from(число)`: снимается, если чекер даёт голому литералу тип
  фиксированного соседа (`p + 24` → `24` становится `u32`) — это новое
  правило языка, решает автор. Широкий результат при ошибке в `a1` —
  решение по ABI. [чтение, предп.]

  `u32` даёт те же байты на диске и тот же экран.
- **3б** — `u64/i64` как сырые два слова: `abi/fixed`, пара в кадре/полях,
