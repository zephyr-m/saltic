## Коротко

- Linux rv32i и Linux x86_64 (перевод) ведут себя **одинаково во всех
  12 пробах**: байт в байт тот же вывод и те же коды выхода [запуск].
  «Три поведения» — это Linux / UEFI / qemu-virt, не четыре.
- Неумение цели выражается тремя разными способами: Linux отдаёт число
  (−38 из `cpu.firmware`, 65498 из `cpu.call`) или падает (`cpu.wait` —
  Illegal instruction, код 132); UEFI отдаёт ошибку `File` для файлов и
  всегда выходит с кодом 0; qemu-virt убивает программу ловушкой на любой
  вызов, кроме write/exit. Ни одна цель не говорит программе «не умею»
  по имени.
- Рантайм уже знает образец «операцию даёт платформа»: `rt_platform_write`
  и `rt_platform_exit` (`rv32i/runtime.saltic:5-6`). Предложение — довести
  этот образец до договора платформы из ~10 меток, отдельного от договора
  машины, с обязательным ответом `NotSupported`.
- Шаг 4 блокируют только три решения: платформа отдельно от машины;
  ошибка `NotSupported`; правило кода выхода. Остальное (время, ввод на
  qemu-virt, куча от платформы, байты UEFI) — после.

## 2. Где расходятся — суть

1. **Неумение без имени.** Один и тот же вопрос «умеешь ли?» имеет три
   ответа: число-код errno (Linux, `cpu.firmware` → −38), ошибка с чужим
   именем (UEFI, файлы → `File`), смерть программы (qemu-virt, ловушка;
   Linux, `cpu.wait`). Программа не может написать переносимый `rescue`.
2. **Выход.** Код теряется на UEFI, уродуется на qemu-virt (двоичный),
   а на всех трёх непойманная ошибка молчит.
3. **Клавиша.** Три разных протокола: termios (Linux tty), 1 байт с
   потерей стрелок (UEFI, труба на Linux), ловушка (qemu-virt). Имена
   `up/down/…` рождаются только там, где `read` отдал 3 байта разом.
4. **Платформенные вещи зашиты в рантайме.** `host.saltic` и
   `terminal.saltic` зовут `ECALL` с номерами Linux напрямую (12 мест
   файлов + 5 терминала + 3 `cpu.*`); только write/exit вынесены в
   `rt_platform_*`. Поэтому UEFI и qemu-virt вынуждены *эмулировать Linux*
   (заглушка переводит номера, ловушка ловит их) вместо того, чтобы
   исполнять договор.
5. **Времени нет** как понятия языка: каждая цель читает свои часы своим
   способом, Linux — никак.

## 3. Предложение: договор платформы

Платформа — то, что окружает программу: вывод, выход, клавиша, файлы,
время, ожидание, прошивка. Договор — список операций с обязательным
поведением и единым способом сказать «не умею».

**Правило неумения.** Операция, которой цель не даёт, отдаёт ошибку
`NotSupported` (системная ошибка id 12, `abi/errors.saltic` — после
`NumberOverflow`), ловится `rescue |e|` как любая другая, печатается именем.
Никогда — ловушка, Illegal instruction, −38, `File` или тихий ноль.
Реализуется одной меткой `rt_platform_unsupported` (A0 = none, A1 = id);
платформа ставит её на все метки, которых не даёт.

| Операция (метка) | Обязана | Может не уметь | Сегодня |
|---|---|---|---|
| `rt_platform_write(fd, ptr, len)` | каждая цель; UTF-8 как есть; что не может показать — `?` за **символ**; короткая запись — не ошибка | — | есть везде; UEFI уже по символу |
| `rt_platform_exit(code)` | каждая; 0 → успех, иначе — неуспех с сохранением числа, где хост умеет | — | UEFI теряет; qemu-virt — двоичным |
| `rt_platform_key()` → строка | блокирующее нажатие; имена `escape/enter/backspace/tab/up/down/right/left`; `""` — конец ввода | да → `NotSupported` | три протокола |
| `rt_platform_file_open/read/write/close` | — | да → `NotSupported` | Linux умеет; UEFI → `File`; qemu-virt → ловушка |
| `rt_platform_now()` → число тактов (28 бит, переход через 0 — `time.elapsed`) | каждая [предп.: у всех трёх есть источник] | — | API нет |
| `rt_platform_wait()` | — | да → `NotSupported` | Linux падает |
| `rt_platform_firmware(piece)`, `rt_platform_call(hi, lo)` | — | да → `NotSupported` | Linux → числа |
| `rt_platform_arguments()` | каждая; argv или `[имя]` | — | в `_start` через `ARGV` |
| `rt_platform_heap()` → байты | потом (аудит 10.5): квота от платформы, не из `cc` | — | при сборке |

Кодовые соглашения те же, что у `rt_*`: аргументы в `ARG0…`, результат в
`VALUE`, ошибка в `ERROR` (`CALL_NO_ERROR` = 0). Рантайм (`host`,
`terminal`) зовёт только эти метки и больше не содержит `ECALL`;
`core/system.saltic` с номерами Linux уходит внутрь Linux-платформы.

**Непойманная ошибка и нехватка аргументов** (аудит «Что первым» п. 4):
`_start` печатает `ошибка: Имя` / `нужно N аргументов` через
`rt_platform_write` и выходит 1 / 64. Это общий код `state.start`, не
платформенный — одинаково на всех целях даром.

**Код выхода по целям** (решение 4 ниже): Linux — число; UEFI — `Exit`
со статусом `EFI_SUCCESS` при 0 и `EFI_ABORTED` (21) иначе, число —
в `ExitData` как у `reply.finish`; qemu-virt — SiFive OK/ERROR плюс число
десятичным в UART.

## 4. Как это ложится на договор машины

**Отдельный договор, не часть `backend`.** Оси независимы: x86 × {Linux,
UEFI}, rv32i × {Linux, qemu-virt}, дальше Thumb-2 × {RP2350, STM32} и
ARM64 × {Linux, голое железо}. Если `syscall(имя)` попадёт в договор
машины (`2026-11-03-contract.md`, §10, «рантайм на договоре»), исполнитель
x86 унаследует Linux, а UEFI снова станет эмуляцией Linux поверх x86.
Предлагаю:

- `compiler/platform.saltic` — договор: имена меток (таблица § 3), роли
  аргументов, id `NotSupported`, навык `append_unsupported(compiler, метки)`.
- Платформа — Box с одним методом `append(compiler)` (как `Executor` с
  методами): `backend/rv32i/platform/linux.saltic` (вырезанные из `host`
  и `terminal` `ECALL`-куски, ~120 строк), `os/target/qemu_virt/platform`
  (уже такой, доработать таблицу), `x86_64_translation/{platform,uefi}`
  (пока готовые байты — см. § 5), в шаге 4 — `x86_64_native/platform/linux`.
- `toolchain` выбирает пару (исполнитель, платформа) по имени цели: `rv32i`
  = (rv32i, linux), `x86_64` = (перевод, linux-stub), `x86_64-uefi` =
  (перевод, uefi-stub), `x86_64-native` = (x86_64_native, linux) — 3–5 строк
  развилки вместо `(target == …)`.
- `syscall(имя)` остаётся **внутри** Linux-платформы: это её способ
  исполнить договор, а не операция машины. В договоре машины появляется
  лишь то, что нужно самим платформам: `wait`, `fence`, `csr_*`
  (qemu-virt), `ecall` как сырая команда исполнителя RV32I.

Так рантайм пишется один раз (путь (б) отчёта о договоре), платформа —
один раз на хост, исполнитель — один раз на архитектуру; три слоя
перемножаются, а не переписываются.

## 6. Что блокирует шаг 4

Родной x86 (шаг 4) пишет `_start`, выход, системные вызовы Linux и образ
ELF64 заново. Если к этому моменту не решено:

1. **Платформа отдельно от машины** — иначе Linux-вызовы лягут в
   `x86_64_native.Executor` и UEFI (шаг 5) придётся вырезать их обратно.
2. **`NotSupported` и `rt_platform_unsupported`** — иначе родная
   Linux-платформа повторит −38/Illegal instruction, а это и есть
   «унаследует три поведения».
3. **Правило кода выхода и печати ошибки** — `_start` родного x86 пишется
   один раз; поменять потом — трогать три платформы.

Не блокирует (можно после шага 4): `rt_platform_now`, ввод на qemu-virt,
куча от платформы, зазор стека на UEFI/qemu-virt, разбор ESC-последовательностей
в `rt_io_key`, правка байтов UEFI (шаг 5).

## 7. Решения для автора (с рекомендацией)

1. **Платформа — отдельный договор** (`compiler/platform.saltic`, Box с
   `append`), пара (исполнитель, платформа) в `toolchain`. Рекомендую: да.
   Альтернатива — `syscall(имя)` в договоре машины — дешевле на 80 строк,
   но зашивает Linux в машину.
2. **Неумение — ошибка `NotSupported` (id 12)**, ловится `rescue`,
   никогда ловушка/число. Рекомендую: да. Альтернатива — отказ при сборке
   («на этой цели `io.file` нет») — противоречит «одна программа на всё
   железо»: программа должна спросить и обойти.
3. **`cpu.wait` на Linux**: `NotSupported` или «вернуться сразу».
   Рекомендую `NotSupported`: ждать прерывания в user mode нечего, тихий
   возврат превратит `always { cpu.wait() }` в горячий цикл.
4. **Код выхода**: Linux — число; UEFI — `EFI_SUCCESS`/`EFI_ABORTED` +
   число в `ExitData`; qemu-virt — OK/ERROR + число десятичным. `out N`
   из `program` кодом выхода **не становится** (как сейчас и как в PLAN —
   «молчаливый выход»): 0 — успех, 1 — ошибка, 64/65 — служебные.
   Рекомендую оставить так и добавить печать имени ошибки.
5. **`io.key` без клавиатуры** (qemu-virt сегодня): `NotSupported` или
   `""`. Рекомендую `NotSupported`: `""` уже значит «конец ввода» на
   Linux, смешивать нельзя.
6. **Имена клавиш — забота рантайма, не платформы**: платформа отдаёт
   байты (UEFI превращает скан-коды в ESC-последовательности Linux),
   `rt_io_key` сам собирает `ESC [ A` → `up` из буфера, читая байт за
   байтом с коротким ожиданием. Тогда труба, tty и UEFI дают одни имена.
   Рекомендую: да, но после шага 4 (не блокирует).
7. **Время**: `rt_platform_now` → такты 28 бит, обязательная операция;
   на Linux `clock_gettime(CLOCK_MONOTONIC)` в микросекундах по модулю
   2²⁸, UEFI — `GetTime` или `rdtsc`, qemu-virt — `mtime`. Рекомендую
   завести в договоре сейчас (одна строка таблицы), реализовать после
   шага 4.
8. **Файлы на UEFI**: `NotSupported` сейчас; позже — через
   `storage/files.saltic` (прошивка умеет FAT) как настоящая реализация
   `rt_platform_file_*`. Рекомендую так.
9. **Байты UEFI до шага 5 не трогать** — принять, что UEFI до тех пор
   теряет код выхода и стрелки. Рекомендую: да; единственное исключение —
