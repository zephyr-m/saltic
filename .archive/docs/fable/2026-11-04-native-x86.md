- Полку не обновляла, `global-check`/`hosts`/`same`/`refresh`, OVMF, Acer не

## 2. Договор платформы (4.П)

`compiler/platform.saltic`: действия `write(fd, ptr, len)`, `exit(code)`,
`key()`, `file_read(path)`, `file_write(path, text)`, `now()`, `wait()`,
`firmware(piece)`, `call(hi, lo)` — метки `rt_platform_<действие>`, соглашение
как у `rt_*`; `append_unsupported(compiler, actions)` даёт метки с
`ERROR = NotSupported` (id 12, `abi/errors`). Платформа — Box с методом
`append(compiler)`, `compiler.compile_machine(ast, heap, executor, platform)`:

| Платформа | Где | write / exit | key | файлы | now | wait | firmware / call |
|---|---|---|---|---|---|---|---|
| Linux | `compiler/platform/linux` (общая для rv32i и перевода; родной x86 даёт те же `syscall(n)` подпрограммами) | ядро | termios + read | openat/read/write/close | — | — | — |
| UEFI (перевод и родной) | `x86_64_translation/stub.Uefi` | ecall 64/93 | 29/63 | — | — | hlt (перевод — ud2, как было) | 500 / 503 |
| qemu-virt | `os/target/qemu_virt/platform.Platform` | UART (как было) | — | — | — | wfi | — |

Рантайм `host`/`terminal` больше не зовёт `syscall`: `rt_file_write_bytes`
строит строку (`rt_file_bytes_text`, режим ячеек сохранён) и зовёт
`rt_platform_file_write`; `rt_cpu_*` — через платформу; intrinsic файлов
указывают прямо на `rt_platform_file_read/write`. Вход: `rt_start_failure`
(«ошибка: Имя», выход 1), `rt_missing_args(n)` («нужно n аргументов», 64).
Тест `tests/platform.saltic` + фикстуры `uncaught`, `needs-args` — в
`tests/run.sh platform` на rv32i, x86_64 и x86_64-native. [запуск]

## 3. Исполнитель x86-64 — как устроен

`backend/x86_64_native.saltic` — `Executor { firmware }`, 67 методов по 1–3
строки, делегируют детям:

- `roles` — карта (решение автора): `VALUE` eax, `ERROR` edx, `ARG2` r8d,
  `ARG3` r9d, `SCRATCH0…5` ecx ebx esi edi r10d r11d, `FRAME` ebp,
  `HEAP_TOP` r15d, `REGION_MARK` r12d, `ESCAPE_MARK` r13d, `STACK` rsp;
  `RETURN` без регистра (store/load пусты, `call`/`ret` родные); `ARG4…ARG7`,
  `ESCAPE_BOTTOM` — слова первой страницы кода `[r14 + 65536 + 4·роль]`
  (страницу резервирует `new_program`; в ELF она отдельный RW-сегмент, в PE
  вся секция RWX). Роль в памяти — через временный регистр из
  `TEMPS` с push/pop; смещения от STACK при этом +8.
- `ops` — пересылки, арифметика, логика, сдвиги, `set*`; особые случаи
  `STACK`: `move(to, STACK)` = `mov r64, rsp; sub r64, r14`, `move(STACK, from)`
  = `lea rsp, [r14 + from]`, `add(to, STACK, x)` = `lea` от rsp минус r14.
- `access` — load/store слов, байтов, полуслов, push/pop (ячейка 4 байта);
  `load` в `STACK` под `cli … sti` при `firmware`.
- `control` — `cmp/test + jcc rel32`, `jmp`, `call` (патчи `REL32`), адреса
  меток `mov r32, imm32` (`ABS32`), `add/sub_checked` через `jo` по длине
  выпущенного кода, `syscall(n)` = `call x86_syscall_<n>`, `wait` = `pause` /
  `hlt`, `fence` = `mfence`.
- `platform` — Linux: `x86_start` (`r14 = 1 << 32`, argv ядра в строки гостя,
  таблица `[argc, argv…]`, `rsp = arguments`, `jmp _start`); подпрограммы по
  `SYSCALLS = [[29, 16, ptr3], [56, 257, ptr2], [57, 3], [63, 0, ptr2], [64, 1, ptr2],
  [93, 60]]` сохраняют всё, кроме `VALUE`; результат с обнулённой старшей
  половиной. Карта гостя как у перевода: строки 64 КиБ, страж 1 МиБ (разрыв
  между сегментами), стек 8 МиБ, аргументы наверху.
- `image` — ELF64: низкая память 0…65535 (RW, её ждёт `core.mem` и канон),
  страница ячеек (RW), код + rodata (RX), data + bss (RW), строки, стек.
- `uefi` — вход `x86_efi_main` (MS x64: сохранить rbx rbp rsi rdi r12–r15,
  `r14` через `call/pop/sub RVA`, SystemTable/ImageHandle/rsp в словах страницы
  ячеек, `SetWatchdogTimer(0…)`, argc = 1, `jmp _start`), подпрограммы
  `x86_syscall_64` (ConOut->OutputString по символу, CR LF, `?` вместо не-ASCII,
  продолжения UTF-8 пропускаются), 93 (rsp прошивки, восемь pop, `EFI_SUCCESS`),
  63 (ReadKeyStroke / WaitForEvent, скан-код → 0x1b), 29 (−25), 500 (кусок
  r14 / SystemTable / ImageHandle), 503 (блок `[функция, 10 аргументов,
  результат]`, тень 32 байта, rsp на 16). Смещения служб — как в
  `os/target/uefi_x86_64/platform/uefi.saltic` [чтение].
- `pe` — PE32+, одна секция `.text` по RVA 65536 (r14 = база образа, адрес
  гостя = RVA), виртуальный размер до конца стека гостя, пустая таблица
  релокаций, вход — RVA `x86_efi_main`.
- `layout` получил нейтральные `PatchKind.REL32` / `ABS32` и `note_patch`.

Что это потребовало от рантайма (он общий): дисциплина «`ret` из той же
точки стека, что и `call`» — три места, где RV32I прощал, а родной стек нет
[запуск, по падениям]:
1. `rt_string_at` / `rt_string_slice` прыгали на `rt_string_bounds` после
   построения кадра — проверка границ перенесена до кадра;
2. сдвиг переноса региона читался посетителем из кадра `rt_region_exit`
   через `STACK` — у родного `call` там адрес возврата; теперь слово bss
   `rt_region_delta`;
3. `rt_region_forward` прыгал из посетителя в `.L_region_abort` родителя —
   теперь ставит флаг `rt_region_abort_flag` (bss) и возвращается, родитель
   проверяет флаг после обходов. Семантика отката та же (копии откатываются,
   указатели восстанавливаются); RV32I-байты изменились, эталоны `tr_*`
   обновлены (и тест `qemu.saltic`: BSS +2 слова).

Нить `state → layout.Program` убрана: `machine = backend.unassigned()`,
65 `state.State` в `tr_*` задают `machine = layout.Program {}`.

## 7. Команды для автора (OVMF и Acer)

```
# образ флешки родным бэкендом (BOOTX64.EFI) и проверка в OVMF
SALTIC_TARGET=x86_64-uefi-native bash os/target/uefi_x86_64/build.sh
bash os/target/uefi_x86_64/run.sh --check          # ждёт «Pressed: k. Bye!»
# то же из tests/run.sh (после обновления полки):
bash tests/run.sh uefi-native
# агент ОС родным бэкендом:
SALTIC_TARGET=x86_64-uefi-native bash os/target/uefi_x86_64/build.sh os/target/uefi_x86_64/agent.saltic
# Acer — как обычно через os/target/uefi_x86_64/tools (upload/check), образ тот же.
```

Пока полка не знает родных целей, `bootstrap/build.sh` подхватывает свежий
компилятор через `SALTIC_BOOTSTRAP_COMPILER=<stage-1 x86_64>` (ELF64
запускается прямо, без QEMU).

Что в UEFI не проверено запуском и где смотреть, если не загрузится
[предп.]: (1) защита образа прошивкой — секция `.text` помечена RWX
(характеристики `0xE0000060`), запись идёт в неё и в резерв 0…65535
(`core.mem` по адресу 4096 — как и перевод); (2) выравнивание `rsp` перед
вызовами прошивки — делаю `and rsp, -16` и тень 32 байта в каждой
подпрограмме; (3) `SetWatchdogTimer` по смещению 0x100 в BootServices,
`WaitForEvent` 0x60, `ConOut` 0x40, `ConIn` 0x30 — сверены с
`platform/uefi.saltic` ОС и дизассемблером заглушки перевода.
