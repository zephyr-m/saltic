## 15.11.2026 — два провала прогона автора (пройдено 116, провалено 2)

Прогон: stage1 из дерева + патч шага 2 на копии. Правки не собирались и не
гонялись (тяжёлое — автор).

1. **forever «строка», долгий рост 8 байт** — не утечка: снимок берётся внутри
   оборота и видит строки самого оборота, а `"поле {n}"` к концу прогона длиннее
   на три цифры (одно слово выравнивания). Замер поправлен: `wide(n)` =
   `WIDE + n % WIDE` — всегда 8 цифр, строки «поле», «предмет», «из навыка»,
   «снаружи» одной длины на всём прогоне. Строка по-прежнему новая каждый оборот,
   утечка мерится как раньше; порог не трогался.
2. **width «группа 20000 по одному» — память исчерпана** — мусор оборотов `drum`
   (старые хвосты и узлы пути `group.add`) копился до выхода из навыка: 20000
   оборотов не влезали в 4 МБ при живых ~200 КБ. Теперь `drum` — регион на весь
   цикл со сжатием по порогу (`MEMORY-MODEL.md`, раздел «Регион drum»): в конце
   оборота, когда занято больше живого плюс 4 КБ (`model.DRUM_SLACK_BYTES`),
   регион сжимается `rt_region_exit` с корнем — группой значений внешних
   переменных, которым тело присваивает (без фиксированных типов). Работа — не
   больше двух копий на выделенный байт; в хранилище ничего не едет, `always` не
   тронут. Файлы: `compiler/codegen/loops.saltic` (`Region`, `region_open`,
   `region_close`, `region_restore`; `tail`/`light_tail` больше не прыгают в
   начало — прыжок в `region_close`), `compiler/codegen.saltic` (ветка drum),
   `compiler/state.saltic` (слоты `$drum_mark:N`, `$drum_limit:N`),
   `memory/model.saltic` (константа). Новых файлов нет.
   - Почему не как у `always` (переезд внешних переменных в хранилище каждый
     оборот): так всё, что строится в drum, уезжало бы в хранилище, с переносом и
     разбором карантина на каждом обороте, а у компилятора (живая куча больше
     512 КБ) карантин не освобождается — хранилище росло бы без возврата.
   - Под вопросом (проверит прогон): размер кода вырос на каждый drum (~15 команд
     плюс 2 на внешнюю переменную), Box, созданные в навыке до drum и
     записываемые в теле указателем, теперь переезжают в хранилище (барьер
     «старше REGION_MARK» — это и делает сжатие корректным без других корней);
     скорость самосборки; эталоны `runtime_bytes` не трогались (новых меток
     рантайма нет).

## 15.11.2026 — проверка цикла обходит только новое

Поймано global-check: `T.f = V` у Box с рёбрами из хранилища обходил весь граф `V`
до `CYCLE_BUDGET` — растущий список Box (`T.list = group.add(T.list, x)`) падал
`CycleCheckExhausted` без кольца (метки сборщика компилятора — обойдено в
`rv32i/machine/layout`; `wasm.asm.seal`, `prog.wa_blocks = group.add(...)` —
`.cache/build/workbench/check-wasm.log`). Предел 4096 не тронут.

Сделано по решению автора — обходить только то, чего не было в старом значении поля
(`MEMORY-MODEL.md`, «Обходится только новое»): старый фронт (старое значение и до
`CYCLE_FRONT` = 32 его детей помечаются заранее) и тень (ребёнок, равный слову той же
позиции в тени родителя того же вида, — старый, не обходится; очередь — пары объект +
слово тени, 4096 пар). Корректность: достижимое из старого значения к Box не ведёт —
иначе кольцо было бы до записи; пропускается только то, что доказуемо достижимо из
старого (сам фронт и слова теней — дети теней). Рантайм общий для всех целей
(executor).

Файлы: `backend/rv32i/runtime/memory/cycles.saltic` (переписан: `rt_cycle_reach`
берёт ARG2 — старое слово ячейки; `emit_reach_shadow`), `runtime/memory/walk.saltic`
(`emit_object_front(…, cap)` — первые cap слов объекта, `emit_object_walk` — он же с
cap 0; слова bss `rt_reach_delta`, `rt_reach_limit`), `runtime/collections.saltic`
(`rt_box_set` передаёт старое слово), `memory/model.saltic` (`CYCLE_FRONT`),
`tests/memory/cycles.saltic` (случаи «толпа по одному» — долгий Box с рёбрами держит
20 000 Box, по одному; «цикл через новый элемент толпы» — CycleForbidden как прежде),
эталоны `tests/machine/runtime_bytes/tr_objects.saltic` (байты rt_box_get/rt_box_set,
688 байт, 49 переходов, метка `rt_cycle_box` в списке внешних) и `tr_image.saltic`
(меток 747, rodata 1641 — сняты сборкой полки с дерева: эталоны ветки были
устаревшими задолго до этой правки, 511 и 1321 не сходились уже).

Проверено: lens-чекер и лимиты канона по всем тронутым файлам; тест собран полкой
(старый рантайм) — «толпа по одному» падает ровно «не уложилась в бюджет», цикл
через новый элемент ловится. Не проверено на машине: новый рантайм (stage1 не
собирался — тяжёлое, автор), wasm после правки (ожидание: seal обходит только новый
блок и его команды), другие цели.

Под вопросом: новый элемент обходится целиком — если он ссылается на старые элементы
списка глубже первого уровня, они обходятся как раньше (мир, где существа держат
друг друга); `group.replaced` у дерева (плоская другого вида) — обход полный, как
было; очередь стала вдвое длиннее в словах (32 КБ на 4-байтном слове, 64 КБ на
8-байтном над HEAP_TOP) — при меньшем зазоре до низа хранилища —
`CycleCheckExhausted`, как и раньше при 16/32 КБ.

     операцию не зовёт): строка `core.group.replaced` в `selfhost/intrinsic`
     (результат `group-replaced` — тип как у add, по третьему аргументу, в
     `checker/types`); кодоген — общий `compile_stored` для add и replaced
     (значение упаковывается, как у add); рантайм `rt_group_replaced` в
     `backend/rv32i/runtime/collections` — общий для всех целей через executor:
     плоская копируется одним rt_alloc, дерево разворачивает `rt_group_flatten`
     (копия уже своя, значение кладётся в неё); index вне 0…count-1 —
