# Neurostack: гипотеза MiniLens

**Статус:** исследовательская идея, не утверждённая архитектура.

## Нейронавык

Нейронавык снаружи не отличается от обычного `skill`:

- получает обычные значения Saltic;
- возвращает обычное точное значение Saltic;
- после обучения не изменяется самовольно;
- дообучается только явно или после обнаруженного неправильного ответа.

Рядом с исходником навыка хранится одноимённая модель:

```text
neurostack/
├── servo_angle.saltic
└── servo_angle.minilens
```

Файл `.saltic` задаёт контракт и обучающие границы. Файл `.minilens` хранит
сформированное внутреннее содержание навыка.

## Одна линза для всех навыков

Архитектура MiniLens выбирается один раз и используется всеми
нейронавыками. Для каждого навыка не ищется отдельный вид сети или модели.
Меняется только содержание одноимённого файла `.minilens`.

Наличие отдельного нейрона для первой реализации не требуется. Основной
объект исследования — сама линза.

## Жизненный цикл

```text
обычный вход
    ↓
нейронавык проверяет, умеет ли линза работать с ним
    ↓
если не умеет — обучает линзу на заданных границах и сохраняет её
    ↓
смотрит на вход через зафиксированную линзу
    ↓
возвращает точное обычное значение
```

Обучение может один раз потребовать много процессорных тиков. Цель линзы —
после фиксации не повторять исходное вычисление десятки раз, а получать тот же
результат значительно более коротким путём.

## Первая гипотеза: адаптивная геометрия

MiniLens хранит маленькое пространство поведения навыка:

- `points` — известные пограничные состояния входа и выхода;
- `cells` — области, образованные этими состояниями;
- `inputs` — привязки аргументов навыка к входному пространству;
- `outputs` — привязки результата к выходному пространству.

Линза не обязана хранить исходную формулу или программу. Она определяет
положение нового входа внутри известной области и переносит это положение в
выходное пространство.

### Servo angle

Границы:

```text
1000 → 0
2000 → 180
```

Внутренний мир:

```text
point 0: 1000 → 0
point 1: 2000 → 180
cell: [0, 1]
```

Вход `1500` находится посередине известной области. Через ту же внутреннюю
координату линза должна получить точный выход `90`.

Возможное представление модели:

```text
minilens 1

input number
output number

point 1000 -> 0
point 2000 -> 180

cell 0 1
```

Это только читаемый эскиз формата, а не утверждённая спецификация.

## Предлагаемая форма исходника

```saltic
neuroskill servo_angle(pulse) {
    learn {
        [1000] => 0
        [2000] => 180
    }

    check {
        [1500] => 90
    }
}
```

- `learn` виден строителю линзы;
- `check` не участвует в обучении и проверяет восстановление внутренней точки;
- вычислительное тело человек не пишет;
- синтаксис пока является эскизом и текущим парсером не поддерживается.

## Почему геометрия может подойти

- архитектура остаётся одной;
- границы естественно становятся опорными точками;
- линза может явно определить, входит ли значение в известный мир;
- простой навык требует мало точек и связей;
- нелинейное поведение можно уточнять добавлением точки и разделением области;
- многомерные входы могут образовывать многомерные области;
- дискретные значения могут разделять пространство на области с точным
  результатом.

Идея родственна кусочным моделям, прототипному обучению, конечным элементам и
деревьям решений, но не обязана буквально повторять ни одну из этих
архитектур.

## Неопределённые вопросы

- точное устройство универсальной болванки MiniLens;
- представление строк, групп и `Box`;
- способ работы с разрывами и несколькими возможными законами между границами;
- критерий «линза умеет»;
- механизм уточнения после бага;
- окончательный текстовый или двоичный формат `.minilens`;
- место и устройство общего строителя и исполнителя.
