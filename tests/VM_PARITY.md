# Сравнение виртуальных машин

Команда `bash tests/5-vm-parity.sh` сравнивает host-VM из `js/4-vm.js`
и VM на Saltic из `s2/vm.saltic`.

Зафиксированный интерфейс self-hosted слоя:

```s
VmFile = Box {
    path = ""
    data = []
}

VmOptions = Box {
    load_address = 4096
    memory_size = 262144
    step_limit = 100000
    program_name = "program"
    arguments = []
    files = []
}

VmResult = Box {
    exit_code = 0
    reason = ""
    pc = "00000000"
    steps = 0
    registers = []
    stdout = []
    stderr = []
    files = []
    trap = ""
}

skill vm_run(image, options) {
    out VmResult {}
}
```

`image` представлен группой страниц, каждая страница — группа не более чем
из 256 байтов. Содержимое файлов, stdout и stderr представлены группами
байтов от 0 до 255. PC и каждый из 32 регистров представлены восьмизначной
шестнадцатеричной строкой: числа Saltic не вмещают полный диапазон RV32I.

Один файл `tests/fixtures/vm-canonical.S` используется во всех сценариях.
В совокупности режимов он исполняет все 40 инструкций RV32I. Нормальный
режим проверяет аргументы и системные вызовы `openat`, `close`, `lseek`,
`read`, `write`, `exit`. Другие точки поведения выбираются первым
аргументом того же ELF:

- `EBREAK`;
- неизвестная инструкция;
- невыровненный PC;
- ошибка чтения памяти;
- ошибка записи памяти;
- неподдерживаемый системный вызов;
- превышение лимита шагов.

Дополнительно нормальный сценарий выполняется как ELF и как плоский образ.
Для каждого запуска строго сравниваются код завершения, причина остановки,
PC, число шагов, регистры, stdout, stderr, выходной файл и текст ловушки.

Все промежуточные результаты сохраняются в `.cache/build/vm-parity/`:

- `guest/` — ELF и плоский образ комплексной программы;
- `bootstrap/` — тестовая Saltic-VM, AST, результат чекера, assembly и ELF;
- `expected/` — состояние и файлы после запуска на JS-VM;
- `actual/` — состояние и вывод Saltic-VM;
- `diff/` — различия по каждому сценарию.
