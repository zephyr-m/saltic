# Быстрый путь модели памяти Saltic v1

**Статус:** принятый и реализованный быстрый путь Saltic v1.

**Цель:** максимально быстро закрыть текущее ядро Saltic v1, не внедряя
регионы, GC, reference counting и проверку времён жизни.

## Основное правило

В Saltic v1 время жизни любого heap-объекта равно времени жизни программы.

Программа получает одну фиксированную квоту памяти при запуске. Allocator
последовательно занимает байты внутри неё. Отдельные объекты не освобождаются,
а вся память возвращается только после завершения программы.

```text
heap base
→ занятые объекты
→ свободная часть квоты
→ heap limit
```

Недостижимый объект остаётся занятой частью квоты. В этой версии он не считается
мусором, который runtime обязан найти и убрать.

## Allocator

`rt_alloc` получает в `a0` размер payload в байтах.

Он:

1. добавляет размер канонического object header;
2. выравнивает полный размер объекта;
3. проверяет результат относительно границы квоты;
4. записывает `payload_bytes` и нулевые flags;
5. возвращает адрес начала объекта;
6. передвигает указатель занятой памяти.

Создающий объект код записывает его `kind`.

```text
kind
payload_bytes
flags
payload
padding
```

## Квота

Размер heap является параметром машинного образа и задаётся в одном месте до
запуска программы.

Размер не подменяется через `sed`, не зашивается независимо в нескольких
скриптах и не выбирается самим allocator.

Минимальное состояние памяти:

```text
base  — начало heap
used  — текущее занятое смещение
limit — конец доступной квоты
```

Точный вес программы равен `used`. Размер каждого объекта дополнительно можно
проверить по его header.

## Исчерпание памяти

Если объект не помещается, allocator не выходит за границу и не расширяет heap
самостоятельно. Текущий runtime завершает программу через
`rt_out_of_memory` с каноническим статусом 65.

Выдача дополнительной памяти без перезапуска не входит в быстрый путь v1.

## Правила для долгой работы

Программа с постоянным циклом должна:

- заранее выделять изменяемые буферы;
- обновлять данные на месте;
- не создавать бесконечную цепочку новых immutable-объектов;
- считать исчерпание квоты допустимым и наблюдаемым результатом.

Это ограничение версии, а не скрытый сборщик мусора.

## Чего нет в Saltic v1

- регионов и арен с разными временами жизни;
- индивидуального `free`;
- `realloc`;
- GC и mark-and-sweep;
- reference counting;
- перемещения живых объектов;
- автоматической проверки времени жизни ссылок;
- автоматического получения новых участков памяти.

## Реализованное состояние

- `rt_alloc` приведён к payload-контракту;
- heap-объекты используют канонический header;
- allocator считает занятую память и проверяет квоту;
- размер heap передаётся как параметр машинного образа;
- heap-подмена через `sed` удалена;
- исчерпание памяти завершает программу статусом 65;
- границы, header и исчерпание покрыты проверками.

Первоначальная грубая оценка составляла **700–1500 новых или изменённых строк**
вместе с интеграцией и тестами.

## Связанный fixed ABI

Сам выбор модели квоты не определяет представление fixed. Отдельным решением
владельца закреплено:

- fixed хранится как raw 32-bit word;
- boxed fixed удаляется;
- единые `rt_fixed_*` получают source kind в `a6`;
- `rt_fixed_convert` дополнительно получает target kind в `a7`.

Таким образом, значение не несёт динамического kind и остаётся raw word, а
runtime получает минимальные метаданные конкретной операции отдельно.

## Возможная Saltic v2

Поздняя версия языка может заменить единый пожизненный heap иерархическими
регионами владения. Такая версия будет иметь отдельный ABI и отдельные правила
времени жизни, поэтому ядро Saltic v1 не потребуется незаметно переделывать под
другую модель.

Полное предложение регионной модели находится в
`MEMORY-MODEL-PROPOSAL.md`.
