# Реестр адаптеров

Оглавление над адаптерами Saltic (драйверы — адаптеры железа). Код и паспорта
не переезжают: адаптер живёт рядом со своей платформой, реестр лишь знает, где
он, и сверяет паспорт с кодом. Позже реестр станет источником для пакетного
менеджера «tarantul». Папка самостоятельна: потом уедет в свой репозиторий,
отдельно от реестра библиотек (`registry/libraries/`).

| файл | что это |
|---|---|
| `adapters.txt` | список: имя и путь без расширения; код — `<путь>.saltic` и папка `<путь>/`, паспорт — `<путь>.passport.txt` |
| `index.json` | индекс, его пишет `just registry`: имя, заголовок, пути, число файлов кода, идентификаторы, своя версия, архитектуры, эффекты по коду, состояние, итог и замечания |

## Паспорт

Поля — как у всех паспортов (`адаптер`, `версия`, `автор`, `роль`, `время
жизни`, `срок`, `эффекты`, `железо`, `протоколы`, `архитектуры`, `примитивы`,
`зависит от`, `среда`, `состояние`) и ещё три для реестра:

- `идентификаторы:` — по чему адаптер узнаёт своё железо, в машинном виде,
  через запятую: `pci 10ec:8168` (vendor:device), `usb 0408` (vendor),
  `uefi simple-pointer` (протокол прошивки);
- `своя версия:` — версия самого адаптера, растёт при правке его кода;
  `версия:` — в составе какого Saltic он вышел.
- `журнал:` — что адаптер пишет в журнал (сам или через агента), чтобы поломку
  на железе читать по журналу, а не гадать; не пишет — «нет» и куда уходит
  ошибка (решение автора 11.11.2026).

## Сверка — `just registry`

Проверяет каждый адаптер списка (устройство — `workbench/registry.saltic`):

1. паспорт есть, все поля на месте, роль — «адаптер»;
2. архитектуры из паспорта известны, и адаптер лежит в папке своей платформы;
3. код чист у `lens check`: разбор, чекер, лимиты канона — у главного файла
   и у всех `*.saltic` в папке адаптера;
4. эффекты: заявленное совпадает с выведенным из кода — нашёл своё устройство
   и пишет в него → «пишет в железо», иначе «только читает»; пишет файлы →
   в паспорте должен быть «диск»;
5. идентификаторы `pci` и `usb` стоят константами в коде.

Провал — замечания по адаптеру и ошибка `RegistryBroken`. Новый адаптер:
паспорт рядом с кодом, строка в `adapters.txt`, `just registry`.

Пределы сегодня: эффекты выводятся по вызовам платформы, а не по потоку
данных; константа идентификатора ищется в тексте как `= число`.
