# Верстак

Инструменты разработки, которыми пользуются автор и агенты. В релизный пакет
не входят. Промежуточные файлы и логи пишутся в `.cache/build/workbench/`.

| Скрипт | Что делает |
|---|---|
| `limits.saltic` | На Saltic, вместо `limits.sh`. Лимиты канона архитектуры: до 512 строк кода в рукописном `.saltic` и до 32 строк шапки. Известные нарушения — в `limits-known.txt` (правит автор): им нельзя расти; падает на новом или выросшем. Вызывается `just limits` и первым шагом `global-check` |
| `release-draft.saltic` | На Saltic, вместо `release-draft.sh`. Черновик релиза по Football Versioning: коммиты с последнего тега по префиксам, предложенный счёт и раздел CHANGELOG в `.cache/build/release-draft.md`. Вызывается `just release-draft [F:B:C]` |
| `global-check.saltic` | Одна проверка всего, `just global-check` (вместо `global-check.sh` и `hosts.saltic`): по очереди — сборка проверок, лимиты канона, самосборка полки с паспортами и время/память против прошлого прогона; затем разом — тесты на rv32i, x86-64 и rv64, тесты ОС, платформы (qemu-virt, UEFI, closure), самосборка на RV64, кодировщик x86. Вид — карточки «подготовка», «проверки разом», «итог»: под веткой её случаи (из строк «случаи:»/«случай:» в `tests/run.sh`), у случая отрезок на шкале времени; в терминале блок живой, в CI — без цвета, раз в 10 с «идут». Журналы — `.cache/build/workbench/check-*.log`. Вызывается и в CI релиза |
| `cards.saltic` | Вид `global-check`: палитра логотипа, карточки со скруглёнными углами, полосы веток и отрезки случаев, метки, пиксельный логотип; в CI — без цвета |
| `receipt.saltic` | Чек картинкой: строки терминала с цветом → клетки → пиксели (Spleen 8×16 из `os/fonts`, рамки и метки — свои маски) → PNG. `global-check` кладёт чек в `чеки/` (вне git): дата, коммит, вердикт в имени |
| `png.saltic` | Кодировщик PNG с палитрой: deflate с готовыми кодами Хаффмана, повторы — соседний байт и строка выше; CRC32 через `bits32` |
| `stamp.saltic` | Время `[ЧЧ:ММ:СС]` у каждой строки вывода скриптов: `bootstrap/stamp.sh` собирает его в `.cache/build/workbench/stamp` и пропускает через него вывод; без часов в компиляторе — прежний цикл bash. Провал команды — код 1 и строка «ошибка: StampedFailed» |
| `perf.sh <компилятор.elf> <исходник>` | Профиль программы под QEMU через `perf`: сколько времени уходит на сам QEMU и на какие функции Saltic |
| `same.saltic` | На Saltic, вместо `same.sh`; `just same [исходники…]`. Проверка рефакторинга компилятора: текущие исходники, собранные компилятором с полки `bootstrap/` и новым stage-1 под rv64, x86_64 и rv32i, должны совпасть побайтово; плюс набор ошибок канона. Оба компилятора работают родными x86-версиями. Вызывается `just same` |
| `same-source.saltic` | На Saltic, вместо `same-source.sh`; `just same-source`. Проверка правки исходников без изменения смысла: все программы (toolchain, канон, тесты, образ ОС) собираются одним компилятором из HEAD и из рабочего дерева и сравниваются побайтово |
| `kit.saltic` | Общее у проверок на Saltic (`same`, `same-source`): строка со временем, запуск через bash, сравнение файлов по байтам, сортировка, хвост журнала. Подключается `use workbench.kit` |
| `x86-encoder-golden.saltic` | На Saltic, вместо `x86-encoder-golden.sh`; `just x86-golden [--print]`. Эталоны кодировщика x86-64: каждую команду из `tests/x86-encoder.saltic` собирает GNU `as` и сверяет байты с тестом; `--print` печатает байты `as` для новых эталонов |

Тяжёлые проверки (`global-check.saltic`, `same.saltic`, `same-source.saltic`) запускает автор.
