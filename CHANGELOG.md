# История изменений

С версии 58:12 номер — счёт Football Versioning «фичи : баги»
([docs/FOOTBALL.md](docs/FOOTBALL.md)). Версии 1.x пересчитаны в начальный
счёт 54:6.

## 58:12 — 2026-11-01

### Фичи

- Saltic работает без Linux: цель `x86_64-uefi` собирает UEFI-приложение
  PE32+, которое прошивка ноутбука грузит с флешки. Вывод идёт в консоль
  прошивки, клавиша читается через её ввод, выход возвращает в прошивку.
  Шаги для флешки — `os/target/uefi_x86_64/README.md`.
- x86-64: переведённый код не зависит от адреса загрузки.
- Проверка `uefi`: образ грузится в QEMU с прошивкой OVMF, пишет на экран и
  читает клавишу.
- Запятые между полями Box в объявлении и литерале:
  `Signal { name = "scan", step = 1, cost = 5 }`. После последнего поля
  запятая запрещена; у `enum` и групп правило прежнее.

### Баги

- Числа больше ±255 собираются как 32-битное слово: раньше компилятор
  считал `n * 8` в своих 29-битных числах, и уже `33554431` печаталось как
  `-33554433`.
- Ошибка загрузки модуля называет модуль и путь и указывает на файл с `use`.
- Переменная не может называться как подключённый модуль: раньше чекер
  читал `file.x` как член модуля, а компилятор — как поле переменной.
- Фиксированное значение (`u8`, `u32`, `i32`…) не уходит из локальных
  переменных навыка: в группе, параметре и `out` оно теряло тип и печаталось
  мусором.
- Поле Box не хранит фиксированное значение: регион мог принять сырое `u32`
  за ссылку и перезаписать его.
- `workbench/perf.sh` передаёт компилятору цель `rv32i`.

### Без гола

- Football Versioning вместо semver.
- Канон языка `soul/seed/canonical` догнал язык; `AGENTS.md` требует
  обновлять его вместе с языком.
- 93 ручных счётчика в `drum` заменены на `beat`.
- Витрина приведена к 1.10.0, план работ обновлён.

## 1.10.0 — 2026-10-31

- Подстановка в строки: `"привет, {name}! x={point.x}"`. Внутри `{}` — имя или
  поле; подставить можно текст, число или `yes`/`no`, иначе ошибка чекера.
  Буквальные скобки пишутся `\{` и `\}`. Весь код переведён: сообщения,
  собиравшиеся по кусочкам через `str.add`, стали одной строкой (чекер −85
  строк).
- Один путь обращения к чужому модулю: только через его короткое имя —
  `io.show`, `str.add`, `greeting.Greeter`. Длинный путь (`seed.str.add`,
  полный путь к Box или константе) — ошибка `long_path` с подсказкой, какой
  `use` добавить. Импорт отдельных имён `use путь { … }` из 1.9.0 убран.
- `use seed` и главный файл `soul/seed.saltic` убраны: программа подключает
  только нужные модули библиотеки и больше не тащит в себя все её помощники.
- Весь код переведён на `модуль.навык` — около 1 900 вызовов, программы
  собирались побайтово как раньше.
- Исправлено: чекер отвергал поле локальной переменной, если её имя совпадало
  с коротким именем модуля (`file.path` рядом с `use seed.io.file`).
- Минификатор удалён: в Saltic почти нечего сжимать.

## 1.9.0 — 2026-10-31

- Стандартная библиотека из настоящих модулей: `soul/seed.saltic` подключает
  `seed.str`, `seed.group`, `seed.io`, `seed.io.file` и остальные. Встроенные
  навыки объявлены словом `native` (`skill len(text) native`), рядом лежат
  помощники на Saltic. `use seed` больше не особый случай загрузчика.
  Бывший `soul/core` переехал в `seed`.
- Импорт имён: `use seed.io { show, key }` даёт `show(...)` без цепочки;
  совпадение имён и несуществующее имя — ошибки чекера.
- `seed.file.*` переименован в `seed.io.file.*`: весь ввод-вывод собран в `io`.
- Ввод с клавиатуры без Enter: `seed.io.key()` возвращает нажатие, стрелки и
  особые клавиши словами (`up`, `enter`, `escape`…); `seed.io.clear()` очищает
  экран. Ctrl+C завершает программу с кодом 130 после восстановления терминала.
- x86-64: одиннадцать самых горячих RV-регистров живут в регистрах x86;
  fib(35) 0,28 → 0,20 с, родной компилятор собирает toolchain за 5 с вместо 7.
- Сборка и самосборка запускают загрузочный компилятор его родной
  x86-версией: самосборка 45 с вместо ~100, toolchain — 6 с вместо 33.
- У каждой строки вывода наших скриптов есть время; `global-check.sh` печатает
  сводку тестов по ходу прогона и сообщает, если прогон оборвался.

## 1.8.0 — 2026-10-31

- Отрицательные литералы: `-5`, `a * -1`, `[1, -2]`. Минус вплотную к числу
  на месте значения даёт литерал; после значения минус по-прежнему оператор.
  Весь код переведён с `0 - N` на `-N`, программы при этом побайтово те же.
- `0 - N` компилируется в одну загрузку константы, как `-N`.
- Компиляторы живут в `bootstrap/` и называются
  `saltic-<версия>-compiler-<процессор>-<платформа>`; рядом с каждым паспорт:
  из каких исходников, чем собран, сходится ли самосборка. В git только
  загрузочный `rv32i-linux`; родной `x86_64-linux` и toolchain для qemu-virt
  самосборка выводит сама и проверяет их свежесть по паспорту.
- Сборка ОС берёт готовый qemu-virt toolchain с полки вместо пересборки.
- x86-64: между кучей и стеком родной программы 1 МБ незамапленной памяти;
  переполнение стека падает сразу, а не портит кучу молча.
- Инструменты: `workbench/global-check.sh` (самосборка, замер, быстрые тесты)
  и `workbench/same-source.sh` (побайтовая сверка всех программ до и после
  правки исходников).
- Документы: план работ `docs/PLAN.md`, новое понимание ядра ОС
  `docs/OS-core.md`, витрина `docs/LANDING.html`; прежние документы по ОС
  перенесены в архив.

## 1.7.0 — 2026-10-31

- Новые слова языка. Внутри `drum` доступен `beat` — текущий элемент группы
  или номер шага; `drum` принимает и число, и группу. `leave` выходит из
  ближайшего `drum`. `pick { (условие) {…} … { иначе } }` выполняет первую
  подходящую ветку.
- Парсер, чекер, компилятор и VM переписаны на `beat`, `leave` и `pick`
  вместо ручных счётчиков: минус около 700 строк при побайтово том же
  результате сборки. Самосборка ускорилась с 39,8 до 32,9 с.
- Смещения кадра больше 2 КБ кодируются через `T6`; инструкция, которую не
  удалось закодировать, останавливает сборку с ошибкой.
- Канон архитектуры требует утвердительных имён флагов: отрицание пишется
  только явным `== no`.
- `workbench/same.sh` проверяет рефакторинг без изменения смысла.

## 1.6.0 — 2026-10-31

- Saltic работает на x86-64 Linux без QEMU. Новый бэкенд `backend/x86_64`
  переводит готовую программу RV32I в x86-64 и записывает ELF64.
- `just native файл.saltic` собирает программу под x86-64 и сразу
  запускает её на компьютере.
- Компилятор, переведённый на x86-64, собирает toolchain за 7,5 с вместо
  37,5 с под QEMU, с побайтово тем же результатом.
- Компилятор собирает сам себя прямо на x86-64 с fixed point, без QEMU.
- Новые проверки: `native` (канон и тест памяти на родном процессоре) и
  `native-bootstrap` (самосборка на x86-64).
- Инструменты разработки собраны в `workbench/`.

## 1.5.0 — 2026-10-31

- Самосборка компилятора ускорилась в 4,3 раза: с 2 мин 01 с до 28 с.
- Литеральные константы, сложение, вычитание и сравнения чисел
  компилируются прямо в код без вызовов runtime.
- Чтение и запись полей Box получают подсказку позиции поля.
- Метки ищутся по индексу вместо перебора всего списка, таблицы символов —
  без лишних проходов.
- Вызовы стали прямыми инструкциями `jal`; программы с кодом больше 1 МБ
  автоматически собираются с дальними вызовами.
- Деление выполняется двоичным методом за 32 шага, делители-степени двойки —
  сдвигом.
- Переход, который не удаётся разрешить, теперь останавливает сборку с ошибкой
  вместо записи нулевого слова в код.
- Добавлен `just fast` — все проверки, кроме `closure` и `bootstrap`.
- В README, философии и `AGENTS.md` указано, что Saltic делается автором для
  себя и своих агентов.

## 1.4.0 — 2026-10-31

- Память переведена на регионы владения: каждый вызов skill освобождает свой
  мусор при выходе, а результат `out` переходит вызывающему. Процесс
  самосборки под QEMU занимает около 142 МБ памяти вместо 381 МБ.
- Нехватка памяти стала системной ошибкой `MemoryExhausted`, которую ловит
  `rescue`; программа продолжает работу вместо завершения с кодом 65.
- Добавлены звуковой драйвер virtio-sound и приложения PIANO и SPACE
  (вращающиеся 3D-формы) в лаунчере.
- Добавлен минификатор исходников: `just minify путь.saltic`.
- Законы и канон проекта собраны в `docs/`, исторические планы и аудиты
  перенесены в `.archive/docs`.

## 1.3.0 — 2026-10-11

- Графическая система Saltic переведена на собственный Full HD-экран
  1920×1080 через QEMU ramfb; лаунчер и существующие приложения согласованы с
  новым пространством.
- Spleen закреплён как системный bitmap-шрифт экосистемы: встроены шесть
  нативных размеров от 5×8 до 32×64, ASCII и русская кириллица, а уровни
  Markdown стали единственным протоколом размера текста.
- Добавлена отдельная витрина типографики с английским и русским алфавитами,
  шестью уровнями заголовков и эталонным образцом Spleen.
- JTML теперь рассчитывает текст по реальным метрикам выбранного начертания, а
  поле ввода корректно считает и удаляет двухбайтовые символы UTF-8.
- Лаунчер расширен живой игрой `SALTIC COLONY`: рабочие самостоятельно добывают
  еду, возвращают её в гнездо и выращивают колонию; игрок может добавлять еду,
  строить стены и стирать объекты непосредственно мышью.
- Колония обновляет только затронутые клетки и служит первым продолжительным
  прикладным сценарием для графики, ввода, модели объектов и памяти Saltic.

## 1.2.11 — 2026-08-23

- Завершён аудит обвязки: полный `just test` теперь проверяет bare-metal
  QEMU-контур, а артефакты неудачного прогона сохраняются для диагностики.
- Окружение разработки зафиксировано через `flake.lock`; Nix остался внешним
  bootstrap-слоем, а сценарии Saltic и `justfile` от него не зависят.
- Релизный workflow проверяет тег до тяжёлого прогона и прикладывает чистый
  Saltic SDK с контрольной суммой без архива, чекпоинта и аудитов.
- Редактор и документация согласованы с реальным языком: удалена несуществующая
  поддержка комментариев и устаревшие команды JavaScript-контура.
- Удалён одноразовый переход `core → seed`, QEMU-проверка избавлена от гонки
  таймаута, а графическая ОС запускается короткой командой `just os`.

## 1.2.8 — 2026-08-23

- Архитектура проекта собрана в согласованные слои `soul/seed`, `soul/core`,
  `soul/craft` и отдельный контур `os`.

- Зафиксированы единые контракты диагностики, ABI и AST, а bootstrap вновь
  доведён до побайтового fixed point.
- Старый JavaScript-контур и прежние тесты перенесены в архив; полный аудит
  согласованности завершён успешным `just test`.

## 1.0.0 — 2026-08-20

Первый стабильный релиз Saltic.

- Достигнут стабильный самохостинг: активные парсер, чекер и компилятор написаны
  на Saltic, а сборки второго и третьего поколений совпадают побайтово.
- Самохостящиеся чекер и компилятор сверены с исходной реализацией на JavaScript

  исходной виртуальной машиной на JavaScript.
- Добавлена единая проверка полного цикла самохостинга с диагностикой прогресса,
  расхода гостевой кучи и места остановки.
