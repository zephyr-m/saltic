## 142:36 — 2026-11-03

### Фичи

- Чекер: глобальные имена — таблица на 64 корзины по хешу вместо перебора
  ~2000 имён на каждый поиск. Самосборка 9,5 → 4,1 с.
- `core.bytes` — родной буфер байтов, изменяемый, как Box: `new`, `count`,
  `get`, `set`; ошибки `ByteOutsideRange`, `BytesBounds`, `InvalidSize`.
  Миллион байтов — 1,9 МБ и 0,03 с против 118 МБ и 0,35 с у группы.
- `bytes.slice` (независимая копия), `bytes.from_group`, `bytes.to_group`.
- `file.read_bytes` и `file.write_buffer` — буфер в файл и обратно.
- Компилятор на буфере: `machine.buffer` хранит образ кусками `bytes` по
  4 КБ вместо Box на каждый байт. Самосборка 227 → 28 МБ и 4,2 → 2,9 с,
  тесты `global-check` 26,7 → 19,2 с и 368 → 46 МБ.

### Баги

- Имена главной программы (`start`, `Point`, `reply`) ломали локальные
  переменные и Box одноимённых имён в любом модуле: теперь голое имя видно
  только из главной программы.
- `io.file.write_bytes` молча обрезал значение до байта (259 → 3): теперь
  ошибка `ByteOutsideRange`, двойник `write_checked_bytes` убран.
- `global-check` помечал ❌ успешную строку со словом «ошибка».

### Без гола

- `soul/seed/tests/machine/translation.saltic` разрезан на 7 файлов в
  `translation/` — по лимиту канона в 500 строк.
- PLAN: баг имён, `write_bytes` и память компилятора решены; буфер байтов
  по шагам; чтение файла — не больше 1 МБ (пока так, решение автора).
