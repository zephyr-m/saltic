# Бэкенды компилятора

Каждый бэкенд — машинный код одного семейства процессоров. Папка с одним
`README.md` — заглушка: бэкенд записан в план, но ещё не начат. Подробно —
`docs/plan/PLAN-3.md`, раздел «Железо и бэкенды»; порядок работ — там же.

Общее лицо — `main.saltic`, **договор машины**: роли регистров
(`VALUE`, `ERROR`, `ARG2…`, `SCRATCH0…`, `FRAME`, `STACK`, `HEAP_TOP`, …;
`ROLE_COUNT` = 21) и операции («положи число», «загрузи слот», «вызови», «перейди, если ноль»,
«вызов платформы»…). `codegen`, `functions`, `state` и рантайм `rt_*`
(`runtime/`, общий для всех; там же общий буфер байтов `buffer`) говорят только на нём — методами Box-исполнителя в
`compiler.executor`. Новый бэкенд = Box с теми же методами (образец —
`rv32i.Executor`) плюс образ и платформа; рантайм достаётся бесплатно.

Устройство (решение автора 22.11.2026): каждая платформа знает только своё,
общее не лежит ни в одной личной папке, исполнитель — в папке своей семьи
(папки семей заведены заранее, чтобы было видно, куда встанет родня).

```
backend/
  main  buffer  image  layout/  runtime/   общее для всех: договор, байты, запись
                                           образа, программа в сборке, рантайм rt_*
  riscv/      общее семьи: instruction, registers, codec, decoder, assembler,
              emit (команды и переходы), fixer (правки RISC-V)
    rv32i/  rv64/
  x86/x86_64/    arm/arm64/    xtensa/lx6/    wasm/wasm32/
```

Правки (переходы и адреса по меткам): общие — `layout` (ADDRESS_WORD, REL32,
ABS32), правки семьи — её чинильщик в `Program.fixer` (у RISC-V —
`riscv.fixer.Fixer`); `layout.resolve` чинит общие сам, остальное отдаёт ему.
