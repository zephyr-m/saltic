# ARM64 — бэкенд

✅ **Есть (12.11.2026): Linux.** Вход — `../arm64.saltic`: исполнитель
договора машины `Executor { fixups }` (все методы `../backend.saltic`) и
`write(path, machine, fixups)` — ELF64 AArch64. Цель `toolchain` — `arm64`
(решение автора 12.11.2026). Под `qemu-aarch64`: канон (и с кучей 4,5 ГБ),
`edges`, `always`, `wide`, дробные, платформа, большие числа — те же выводы, что
у остальных целей; компилятор, собранный под ARM64, собирает сам себя байт в
байт (неподвижная точка) и компилятор x86-64 — тот же, что у родного x86-64.

- **Набор команд:** AArch64 (ARMv8-A и новее) — не Thumb-2, отдельный бэкенд.
- **Что откроет, ступеньками:** программы под Linux и Android (статический
  ELF, Termux) → Raspberry Pi 4/5 и Orange Pi на голом железе («головной
  мозг» робота) → своя ОС на телефоне — мечта на потом.
- **Проверка:** `qemu-aarch64` в `just test` (случаи `arm64`, `arm64-encoder`,
  `fraction`, `wide`, `platform`); в CI релиза — бесплатный сборщик
  `ubuntu-24.04-arm`, без эмулятора (канон, `edges`, самосборка). Кодировщик
  против GNU as — `just arm64-golden` (binutils для aarch64 из nix).
- **Документация:** Arm Architecture Reference Manual for A-profile (ARM).

Общих команд ни с кем нет, поэтому исполнитель целиком свой. Раскладка —
общая `rv32i/machine/layout` (адрес 65536, без низкой памяти: адрес 0 ядро на
настоящем железе не даёт), ELF — общий `../../linker/elf64` (номер машины 183).

| Что | Где |
|---|---|
| Вход: `Executor`, `fresh`, `write` | `../arm64.saltic` |
| Роль → регистр: все 21 роль в регистрах | `roles` |
| Слова команд (32 бита, в bits32) | `encoder` |
| Константы (movz/movn/movk), арифметика, логика, сдвиги, сравнения, умножение, деление, дробные | `ops` |
| ldr/str, смещения вне команды — через x16; push/pop на x28 | `access` |
| Переходы, вызовы, адреса меток (adrp + add), правки `Fixups`, вызов ядра | `control` |
| Linux: вход `arm64_start` (x28 = sp, прыжок на `_start`) | `platform` |
| ELF64 AArch64 — общий с RV64 | `../../linker/elf64.saltic` |
| Эталоны кодировщика и сверка с GNU as | `tests/arm64-encoder.saltic`, `workbench/check/arm64-encoder-golden.saltic` |

Роли (решение автора 12.11.2026): `VALUE`, `ERROR`, `ARG2…ARG7` — x0…x7,
`SCRATCH0…SCRATCH5` — x9…x14, `HEAP_TOP`, `ESCAPE_BOTTOM`, `REGION_MARK`,
`ESCAPE_MARK` — x19…x22, `FRAME` — x29, `RETURN` — x30, `STACK` — x28. Вне
ролей: x8 — номер вызова ядра, x16 и x17 — временные исполнителя.

Решения исполнителя (не автора):
- **Стек договора — x28, а не sp.** sp на ARM при доступе к памяти обязан быть
  выровнен на 16, а слово договора — 8. sp ядра не трогается (он нужен ядру
  для сигналов), вход кладёт его в x28.
- **Правки переходов — свои (`control.Fixups`), не `layout.Patch`.** Поля
  адреса у ARM 26 и 19 бит и adrp со страницами; `layout` общий и на пределе
  лимита строк. Список правок живёт в исполнителе, `toolchain` отдаёт его в
  `write`.
- **Вызовы ядра — прямо `svc #0`.** Номера общей таблицы Linux у ARM64 те же,
  что у RISC-V; часы — номер RV64 (113). Отличие одно: флаг `O_DIRECTORY` у
  ARM 16384, а не 65536 — `syscall` переводит его у `openat`.
- **add_checked** — adds/subs и csel по флагу переполнения, без переходов.
- **Логическое с числом** — команда с маской для 2^k − 1 и −2^k (так лежат
  `TAG_MASK` и его дополнение), иначе через x16.

- **Страницы 64 КБ.** У ядер ARM страница бывает 4, 16 (новые телефоны с
  Android 15+) и 64 КБ (часть серверов). Сегменты ELF выровнены на 64 КБ
  (`platform.pages`: rodata дополнена нулями, data — с новой страницы), так
  что образ годится всем трём; цена — до ~128 КБ нулей в файле. Проверено
  только на 4 КБ: `qemu-aarch64` размер страницы не меняет.
