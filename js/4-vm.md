# RV32I VM

`4-vm.js` — виртуальный процессор Saltic для RV32I.

## Реализовано

- все 40 инструкций RV32I;
- 32 регистра `x0–x31` и `pc`;
- линейная память;
- загрузка ELF32 и flat binary;
- стек, `argc` и `argv`;
- терминальный ввод и вывод;
- файловые операции через `ECALL`;
- exit code, `EBREAK`, traps и лимит шагов.

Системные вызовы:

```text
openat  56   открыть или создать файл
close   57   закрыть файл
lseek   62   изменить текущую позицию внутри файла
read    63   прочитать данные
write   64   записать данные
exit    93   завершить программу
exit_group 94
```

## Проверка

Проверка выполнена независимым toolchain:

```text
riscv32-none-elf-gcc 14.3.0
-march=rv32i
-mabi=ilp32
```

GCC собрал настоящие RV32I ELF-программы, которые затем исполнил `4-vm.js`.

Подтверждено:

- исполнены все 40 инструкций RV32I;
- проверены арифметика, сравнения и сдвиги;
- проверены условные переходы, `JAL` и `JALR`;
- проверен `JALR` с одинаковыми `rd` и `rs1`, который используется linker-ом для дальнего `call`;
- проверены byte, halfword и word load/store;
- ELF-сегменты загружаются в память;
- программа получает `argc` и `argv`;
- программа создаёт, записывает, закрывает и читает файл;
- `lseek` меняет позицию файла: после перехода на байт `2` прочитано `cd`;
- прочитанные данные выводятся в терминал;
- `ECALL` завершает программу с ожидаемым exit code;
- `EBREAK` останавливает VM с причиной `break`.

Проверочная программа записала в файл и вывела:

```text
IO
```

Все выполненные проверки завершились успешно.

## Ещё не проверено

- стандартный RISC-V architectural test suite;
- большие реальные программы;
- длительное исполнение и производительность.

Текущий результат доказывает работоспособность основной машины и системной среды,
но не заменяет дальнейшую проверку официальным набором тестов.
