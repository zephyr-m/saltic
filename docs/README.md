# Документация S

Этот индекс нужен, чтобы не утонуть в документах.

Не все файлы имеют одинаковый статус. Часть документов является каноном текущего направления, часть — рабочей спецификацией, часть — черновыми деталями.

## Читать сначала

Эти документы задают направление проекта.

```text
roadmap.md      порядок движения
foundation.md   фундамент перед world MVP
world.md        целевая физическая эмуляция мира
libraries.md    карта библиотечных слоёв
```

Если нужно быстро понять, куда идёт S, читать в этом порядке.

## Рабочая спецификация языка

Эти документы описывают текущий язык и его поведение.

```text
grammar.md
syntax.md
types.md
errors.md
checker.md
runtime.md
```

Они должны оставаться ближе к тому, что реально парсится, проверяется и запускается.

## Tooling и bootstrap

```text
commands.md
racket.md
```

Здесь описываются команды, Racket bootstrap и текущий способ работать с проектом.

## Архитектурные черновики

Эти документы важны, но пока являются детализацией vision.

```text
c-interop.md
sys.md
host.md
stdlib.md
core.md
informatics.md
engine.md
agent.md
```

Их можно менять, сливать и упрощать по мере того, как появляется исполняемая практика.

## Остальное

```text
philosophy.md
non-goals.md
```

Фиксируют ограничения и мотивацию.

## Правило

Если документ не помогает принять инженерное решение или проверить следующий маленький milestone, его надо упростить, слить с другим документом или удалить.

Документация должна помогать строить S, а не заменять строительство S.
