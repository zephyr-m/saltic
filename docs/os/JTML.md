# JTML — четыре атома

**Решение автора, 08.11.2026.** Интерфейс Saltic строится по атомарному
дизайну: в JTML ровно четыре фундаментальных примитива, всё остальное —
их сборки. Дизайн-система вырастает из JTML, а не наоборот.

| атом | что это |
|---|---|
| `box` | компонует и хранит в себе что угодно: колонка или ряд, отступы, промежутки, рамка, доля свободного места (`grow`) |
| `text` | текст; с `id` — цель щелчка |
| `field` | поле для текста |
| `slider` | ползунок: `value`, `min`, `max` |

Кнопка — это `box` с рамкой и `text` внутри, флажок — `box` в `box`, вкладки —
ряд `box` с текстом. У компонентов нет своего рисующего кода. Чужой тег при
чтении — ошибка `UnknownAtom`.

```json
{"box": {"flow": "row", "gap": 8, "padding": 12, "border": 1, "children": [
    {"text":   {"value": "Громкость"}},
    {"slider": {"id": "volume", "value": 40, "min": 0, "max": 100}},
    {"field":  {"id": "name", "value": "Зефир"}}
]}}
```

## Где живёт

- `os/ui/jtml.saltic` — лицо: раскладка, Runtime (значения полей и
  ползунков, фокус, цели щелчков), рисование. Tab — следующий в фокус,
  стрелки двигают ползунок, щелчок ставит его положение.
- `os/ui/jtml/atom.saltic` — атомы: виды узлов, Node, конструкторы.
- `os/ui/jtml/slider.saltic` — ползунок без дерева: пределы, шаг, щелчок,
  рисунок.
- `os/ui/jtml/read.saltic` — текст JTML → дерево атомов.
- `os/ui/jtml/reader.saltic` — разбор JSON-подмножества (переехал из
  uiengine).
- Проверка — `tests/jtml.saltic`.

## uiengine

`os/uiengine` с 58 рисуемыми компонентами — мусор по решению автора. Он уходит
в `.archive/`, когда его пользователи (программы Acer: careos, chat, web,
tasks, полка агента) переедут на JTML из четырёх атомов.

## GodMode

**Решение автора, 10.11.2026.** Обычно программа собирается только из
закрытой библиотеки компонентов (около 10 тысяч, все из четырёх атомов) и
рисуется в дизайн-системе пользователя: так везде один вид, а тёмным паттернам
негде жить. Для тех, кому этого мало, в движке интерфейса будет особый режим
**GodMode**: он снимает ограничения закрытой библиотеки и даёт полную свободу
рисовать что угодно.

Как он включается, кто вправе его давать и как пользователь видит, что
программа рисует сама, — пока не решено.
