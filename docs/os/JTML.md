# JTML — пять атомов

**Решение автора, 08.11.2026** (пятый атом `circle` — 18.11.2026). Интерфейс
Saltic строится по атомарному дизайну: в JTML ровно пять фундаментальных
примитивов, всё остальное — их сборки. Дизайн-система вырастает из JTML, а не наоборот.

| атом | что это |
|---|---|
| `box` | компонует и хранит в себе что угодно: колонка или ряд, отступы, промежутки, рамка, доля свободного места (`grow`) |
| `text` | текст; с `id` — цель щелчка |
| `field` | поле для текста |
| `slider` | ползунок: `value`, `min`, `max` |
| `circle` | круг, кольцо или дуга: `size` (поперечник), `border` (толщина кольца), `sweep` (градусы дуги, 0…360, по умолчанию 360) и `start` (откуда, −90 — 12 часов), `fill`, `edge`; дети — в центре круга; `sweep` вне 0…360 — `BadSweep` |

Кнопка — это `box` с рамкой и `text` внутри, флажок — `box` в `box`, вкладки —
ряд `box` с текстом. У компонентов нет своего рисующего кода. Чужой тег при
чтении — ошибка `UnknownAtom`.

```json
{"box": {"flow": "row", "gap": 8, "padding": 12, "border": 1, "children": [
    {"text":   {"value": "Громкость"}},
    {"slider": {"id": "volume", "value": 40, "min": 0, "max": 100}},
    {"field":  {"id": "name", "value": "Зефир"}}
]}}
```

## Слои

**Решение автора, 16.11.2026.** Наложение — только явными слоями, а не
«детьми друг на друге». У `box` либо `children` (раскладываются рядом), либо
`layers` (каждый слой на всю внутреннюю площадь, рисуются по порядку, первый —
внизу). Слой — не атом, а часть `box`, с обязательным именем:

```json
{"box": {"layers": [
  {"layer": {"name": "сетка", "children": [ ... ]}},
  {"layer": {"name": "свечи", "flow": "row", "gap": 3, "children": [ ... ]}},
  {"layer": {"name": "цена",  "children": [ ... ]}}
]}}
```

Ошибки чтения: `ChildrenAndLayers`, `NamelessLayer`, `NotLayer`.

## Свойства: всё, что умеет CSS, без его лишнего

**Решение автора, 16.11.2026.** JTML не уступает CSS по возможностям, но не
повторяет его свойства: одна раскладка вместо пяти, один отступ, одна единица,
слои вместо position и z-index, стили по имени вместо каскада.

| что | свойства | заменяет в CSS |
|---|---|---|
| раскладка `box` | `flow` row/column, `wrap`, `justify` start/center/end/between, `align` start/center/end/stretch, `gap` | flex, grid, float, table, inline |
| отступ | `padding` числом или `[верх, право, низ, лево]`; между детьми — `gap` родителя | margin, padding, схлопывание |
| размер | `width`, `height` в пикселях, `grow` — доля свободного | px, em, rem, %, vh, flex-basis |
| вид `box` | `fill` (фон), `edge` (цвет рамки), `border` (толщина), `radius`, `shadow` | background, border-*, border-radius, box-shadow |
| текст | `size` normal/big/huge, `weight` regular/bold, `cut` — обрезать с «...», `tone`, `align` | font-*, text-overflow, color |
| наложение | `layers` | position, z-index |
| стили | `style` — имя стиля из словаря `styles` страницы; свойства узла поверх стиля, наследования нет | class, каскад, специфичность |
| состояния | `hover`, `focus`, `press` — свойства, которые меняются в этом состоянии | :hover, :focus, :active |

Цвета — имена из палитры экрана (`tone`, `fill`, `edge`). Единица — пиксель и
доля `grow`, других нет. Старый `tone` у `box` (фон без рамки, цвет рамки при
`border` 1, заливка при толще) работает, пока программы не переедут на `fill` и
`edge`.

Делается по шагам, каждый виден на бирже Acer: текст → вид `box` → раскладка
→ стили → состояния. Прокрутка, отзывчивость и движение — потом.

## Где живёт

UIEngine — библиотека реестра (`git@github.com:zephyr-m/saltic-registry.git`,
пути ниже — внутри него); в Saltic приезжает пакетом tarantul, программы пишут
`use tarantul.uiengine.…`.

- `registry/libraries/uiengine/jtml.saltic` — лицо: раскладка, Runtime (значения полей и
  ползунков, фокус, цели щелчков), рисование. Tab — следующий в фокус,
  стрелки двигают ползунок, щелчок ставит его положение.
- `registry/libraries/uiengine/jtml/atom.saltic` — атомы: виды узлов, Node, конструкторы.
- `registry/libraries/uiengine/jtml/slider.saltic` — ползунок без дерева: пределы, шаг, щелчок,
  рисунок.
- `registry/libraries/uiengine/jtml/read.saltic` — текст JTML → дерево атомов.
- `registry/libraries/uiengine/jtml/reader.saltic` — разбор JSON-подмножества (переехал из
  uiengine).
- Проверка — `tests/jtml.saltic`.

- `registry/libraries/uiengine/jtml/calls.saltic` — вызов жителя из программы
  (`calls.call(имя, свойства)`), `jtml/measure.saltic` — размеры.

## Жители

Компоненты UIEngine — жители закрытой библиотеки
`registry/libraries/uiengine/library/level-2…4/*.jtml`, строго по этажам
(решение автора 17.11.2026): 2-й — только из атомов, 3-й — только из жителей
2-го, 4-й — только из жителей 3-го; `box` без вида (полка) — раскладка, можно
везде. Сборщик `library/build.saltic` пишет `library.saltic` и падает
`LevelBroken`, если житель берёт не со своего этажа. Темы — `themes/`, выбор
по имени (`themes.named`). Язык вида — [docs/design/LANGUAGE.md](../design/LANGUAGE.md).

## Старый uiengine

`os/uiengine` (canvas, fonts, icons, shapes) — остаток прежнего движка с
рисуемыми компонентами, мусор по решению автора. Он уходит в `.archive/`,
когда его последние пользователи (программы Acer: careos, chat, web, jumper, clay, cube, land и другие) переедут на
JTML.

## GodMode

**Решение автора, 10.11.2026.** Обычно программа собирается только из
закрытой библиотеки компонентов (замысел — около 10 тысяч, сейчас 141 житель,
все из атомов) и
рисуется в дизайн-системе пользователя: так везде один вид, а тёмным паттернам
негде жить. Для тех, кому этого мало, в движке интерфейса будет особый режим
**GodMode**: он снимает ограничения закрытой библиотеки и даёт полную свободу
рисовать что угодно.

Как он включается, кто вправе его давать и как пользователь видит, что
программа рисует сама, — пока не решено.
