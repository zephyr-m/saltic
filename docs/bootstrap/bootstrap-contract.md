# Bootstrap Contract

Этот документ фиксирует, что Racket bootstrap может делать, а что не должен делать.

## Разрешено

- парсить S;
- проверять S;
- исполнять S;
- печатать diagnostics;
- давать минимальные host-операции для ранних примеров;
- помогать отлаживать syntax, checker и runtime.

## Разрешено только временно

- `host.io.println`
- `host.file.read`
- базовые `host.str.*`
- базовая `host.math.*`

Если такая операция нужна только как мост к будущей `std`, она должна быть названа как временная и не выглядеть как финальный API языка.

## Запрещено

- доменная логика;
- бизнес-логика;
- финансы как отдельная предметная область;
- world mechanics;
- package ecosystem;
- пользовательские удобства, не связанные с ближайшим milestone;
- новые абстракции, не описанные в документации проекта.

## Правило удаления

Каждый bootstrap primitive должен иметь одно из трёх оправданий:

1. без него не живёт текущий parser/checker/runtime;
2. без него нельзя показать ближайшую полезную программу;
3. он нужен как временный мост к `std` или `sys`.

Если оправдание исчезло, primitive должен быть удалён или заменён на более высокий слой.

## Как не расползаться

- Не добавлять bootstrap API ради удобства примера.
- Не переносить в bootstrap код, который должен жить в S.
- Не закреплять временные имена как канон.
- Не строить доменную логику в backend только потому, что там проще.
