# Не цели

Этот документ защищает S от расползания.

S может вырасти в большой язык и экосистему, но `v0.1` должна быть маленькой. Если первая версия попытается решить всё сразу, язык не родится.

## Не цель v0.1: полноценный компилятор

На первом этапе не нужен оптимизирующий компилятор.

Сначала нужно получить:

```text
.s source -> parser -> AST -> checker -> interpreter
```

Компиляция в machine code появится позже.

## Не цель v0.1: backend под собственную ISA

Собственная архитектура — финальная цель, но её ещё нет.

S не должен ждать железо, чтобы начать жить.

До появления ISA нужно подготовить:

- грамматику;
- AST;
- checker;
- interpreter;
- IR;
- маленькую std;
- реальные примеры.

## Не цель v0.1: самохостинг

Самохостинг — важная долгосрочная цель, но не первый milestone.

До самохостинга должны появиться:

- parser;
- formatter;
- checker;
- interpreter;
- toolchain;
- несколько реальных программ на S.

## Не цель v0.1: большая стандартная библиотека

Стандартная библиотека не должна сразу покрывать всё.

Минимум важнее широты:

- `std.io`;
- `std.str`;
- `std.math`;
- несколько runtime helpers.

Остальное можно добавлять только после появления рабочих примеров.

## Не цель v0.1: все доменные ядра

L3 Core — сильная идея, но не задача первой версии.

Не нужно сразу делать:

- `core.physics`;
- `core.chemistry`;
- `core.biology`;
- `core.history`;
- `core.economics`;
- весь каталог доменных знаний.

Для раннего этапа достаточно держать vision и, возможно, экспериментировать с:

- `core.math`;
- `core.logic`.

## Не цель v0.1: package manager

SPM и package ecosystem не нужны до появления языка, на котором можно писать маленькие программы.

Сначала:

```text
parse -> check -> run
```

Потом packages.

## Не цель v0.1: сложная объектная система

`Box` не должен превращаться в class/object framework.

В первой версии `Box` должен быть простым контейнером данных или даже оставаться в статусе открытого вопроса.

Нужно избегать:

- наследования;
- сложных методов;
- скрытой динамики;
- магического поведения;
- множества способов описывать структуру данных.

## Не цель v0.1: много вариантов одной конструкции

S существует, чтобы уменьшать выбор.

Поэтому в v0.1 не нужны:

- `for`;
- `while`;
- `loop`;
- `foreach`;
- несколько форм `return`;
- несколько систем обработки ошибок;
- несколько стилей объявления переменных.

Один базовый путь лучше пяти удобных вариантов.

## Не цель v0.1: максимальная выразительность

S не должен соревноваться с языками, где можно выразить любую абстракцию любым способом.

Цель первой версии:

- предсказуемость;
- читаемость;
- простая генерация агентами;
- простая проверка toolchain;
- автономность без интернета.

## Не цель v0.1: идеальный синтаксис

Синтаксис будет меняться.

Нельзя застревать на идеальном названии каждой конструкции до появления parser.

Если синтаксис можно распарсить, отформатировать, проверить и объяснить, он достаточно хорош для эксперимента.

## Не цель v0.1: production-ready язык

Первая версия не обязана быть пригодной для production.

Она должна доказать:

- язык можно парсить;
- язык можно проверять;
- язык можно исполнять;
- человек может писать на нём без справочника;
- агент может генерировать его без лишней свободы.

## Главный запрет

Не добавлять большую идею, если она не помогает ближайшему milestone:

```bash
racket tools/parse.rkt examples/basic.s
```

Пока parser не работает, все большие идеи остаются в vision, а не в реализации.
