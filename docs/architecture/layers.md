# Layers

Этот документ фиксирует канонические слои S.

S должен расти как система, но не должен становиться жирным языком. Поэтому
ядро остаётся маленьким, а рост уходит в стандартную библиотеку, доменные ядра
и внешние пакеты.

## Карта слоёв

```text
L4 packages
  прикладные пакеты, интеграции, экспериментальные возможности

L3 core
  формальные домены: physics, geometry, logic, language, agents, render

L2 std
  базовые инструменты для обычных программ: io, file, time, math, str, group

L1 runtime / kernel
  выполнение, память, время, безопасность, объектная среда, actor substrate

bootstrap host
  временные возможности текущего backend, пока S ещё не держит себя сам

toolchain
  parser, checker, formatter, runner, tests, diagnostics

target machine
  будущая аппаратная и виртуальная машина исполнения
```

## Смысл слоёв

### L1 runtime / kernel

L1 содержит физику исполнения языка: как программа живёт, как тикает время, как
существуют объекты, как работает память, как соблюдаются базовые гарантии.

В L1 можно класть только то, без чего нельзя честно выполнить S-программу.

Примеры:

- time substrate
- object identity
- world/object lifecycle
- memory model
- safety boundaries
- actor substrate

### L2 std

L2 содержит минимальные инструменты, которые почти любая программа имеет право
ожидать из коробки.

Std не должен знать доменную физику мира. Он даёт простые операции и стабильные
имена.

Примеры:

- `core.io`
- `core.file`
- `core.time`
- `core.math`
- `core.str`
- `core.group`

### L3 core

L3 содержит формализованные области знаний. Это не синтаксис языка и не
runtime. Это библиотеки с ясными моделями, типами, законами и примерами.

В L3 можно добавлять только то, что имеет дисциплину и внутреннюю структуру.

Примеры:

- `core.physics`
- `core.geometry`
- `core.logic`
- `core.language`
- `core.render`
- `core.agent`
- `core.audio`
- `core.vision`

### L4 packages

L4 содержит всё прикладное, спорное, внешнее и экспериментальное.

Если возможность нужна только одному приложению, зависит от внешнего сервиса или
ещё не доказала право быть частью S, она начинается в L4.

Примеры:

- game engine package
- marketplace package
- neural method package
- device integration package
- protocol adapter

### Bootstrap host

Bootstrap host — временная опора текущей реализации. Сейчас S исполняется через
Racket, поэтому часть возможностей может жить в host-слое.

Host-слой не имеет права определять смысл языка. Он только помогает текущей
версии дожить до собственного runtime.

### Toolchain

Toolchain обслуживает язык, но не является языком.

Инструменты могут знать о синтаксисе и диагностике, но не должны становиться
местом, куда прячется стандартная библиотека или доменная логика.

### Target machine

Target machine — будущая среда, где S будет исполняться без зависимости от
текущего host-стека.

Этот слой нужен для проектирования железа, VM и будущей ОС, но он не должен
ломать текущую практику написания S-программ.

## Правило размещения

Если возможность нужна для выполнения любой S-программы, это кандидат в L1.

Если возможность нужна большинству обычных программ, это кандидат в L2.

Если возможность описывает формальную область мира, это кандидат в L3.

Если возможность прикладная, внешняя или экспериментальная, она должна начинать
жизнь в L4.

Если возможность существует только из-за текущего Racket backend, она должна
оставаться в bootstrap host и иметь путь к удалению.

Если возможность нужна только инструментам разработки, она относится к
toolchain.

## Запреты

- Не класть доменную логику в runtime.
- Не класть стандартную библиотеку в toolchain.
- Не расширять синтаксис, если задачу можно решить библиотекой.
- Не считать host-возможность частью языка.
- Не переносить эксперимент сразу в core.
- Не делать пользователя ответственным за низкоуровневый actor substrate в
  обычном S-коде.

## Тест на новый элемент

Перед добавлением новой возможности нужно ответить:

1. Без этого нельзя выполнить S-программу?
2. Это нужно почти каждой программе?
3. Это формальная область знаний?
4. Это прикладной пакет или эксперимент?
5. Это временная поддержка текущего backend?
6. Это инструмент разработки?

Первый уверенный ответ определяет слой.
