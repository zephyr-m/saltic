## Основное правило

Программа получает одну квоту памяти. Каждый вызов skill открывает регион.
Всё, что skill создал, принадлежит его региону. Когда skill завершается,
результат `out` переходит вызывающему, а остальная память региона
освобождается целиком. Оборот `always` — тоже регион. Цикл `drum` — регион на
весь цикл со сжатием по порогу (ниже).

Долгое — то, что переживает регион: значение, записанное в поле долгого Box.
Оно живёт в **хранилище**, отдельной части кучи со своим учётом. Записал
`box.field = value` — рантайм сам решил, долгое ли это, и переложил. Старое
значение освобождается при выходе из региона, в котором его перезаписали (у
вечной программы — в конце оборота), если его больше никто не держит.

Сборщика мусора нет: ни обхода мусора, ни пауз. Работа пропорциональна
сделанному (записям и перезаписям), а не накопленному.

## Куча

```text
saltic_heap_start                                                конец квоты
│ регионы родителей │ регион текущего skill │ свободно │ страницы хранилища │
                    ↑REGION_MARK            ↑HEAP_TOP  ↑STORE_BOTTOM
```

- `HEAP_TOP` — следующий свободный байт региона; выделение — движение `HEAP_TOP`.
- `STORE_BOTTOM` — низ хранилища: страницы по 4 КБ берутся с конца квоты вниз.
- Нехватка — когда регион и хранилище встретились (`MemoryExhausted`).
- Свободная середина служит и рабочим массивам переноса (над `HEAP_TOP`).

## Слово объекта

Заголовок объекта — вид, байты нагрузки, слово учёта (поле «флаги», читается и
пишется целым словом). У объекта региона слово учёта — 0 или `адрес переезда | FORWARDED`:
объект переехал в хранилище, и Box по старому адресу читается и пишется по новому
(`rt_box_get`/`rt_box_set`, равенство Box). У объекта хранилища: бит
`STORE_QUARANTINED` (в карантине), `STORE_BOX_FREE` (группа без Box внутри),
`STORE_MARK` (временная метка обхода) и от бита 4 — **счётчик рёбер
хранилище → хранилище**. Слоты стека и объекты регионов в счётчике не участвуют.
Константы — в `compiler.memory.model`.

## Хранилище

Раздатчик (`runtime/memory/store.saltic`): страницы по 4 КБ; верх хранилища
занимает карта свободных страниц (бит на страницу), запрос n страниц — n подряд
свободных по карте, иначе низ хранилища вниз. Объекты до 512 байт — ячейками
классов 16…512 байт; у страницы свой список свободных ячеек и счётчик занятых,
опустевшая страница возвращается в карту (а значит, годится и под крупный
объект). Крупные — прогон страниц целиком, по освобождении — обратно в карту.
Отказ в страницах — разбор карантина до конца (`rt_quarantine_drain`) и вторая
попытка; это единственный путь без границы времени — восстановление после
нехватки, иначе ошибка была бы ложной.

Перенос (`memory/move.saltic`, `rt_store_move`): значение региона уезжает в
хранилище обходом в ширину по очереди над `HEAP_TOP`. Строка и группа —
копией, оригинал помечается `FORWARDED` (общие подобъекты не дублируются; узлы
дерева, уже лежащие в хранилище, не копируются — счётчик +1). Box — переездом:
оригинал остаётся пересылкой до конца региона, тождество Box сохранено.
После копирования: счётчики рёбер, проверка цикла внутри перевезённого (Кан по
степеням входа), пометка `STORE_BOX_FREE`. Нехватка посреди переноса — откат:
пересылки сняты, ячейки отданы, поле не записано, старое значение целое.

`bytes` рождаются сразу в хранилище (`bytes.new`, `bytes.slice`): буфер
изменяем, и один адрес на всю жизнь дешевле пересылок. Буфер из региона
(`file.read_bytes`) после переезда читается и пишется по адресу переезда;
платформенная запись такого буфера после переезда читает оригинал — известный
край, не чинить без нужды.

## Запись в поле (`rt_box_set`)

1. Box в хранилище — путь хранилища.
2. Box старше текущего региона (`REGION_MARK`) и значение — указатель кучи —
   Box сам переезжает в хранилище (и в карантин: держит его слот), потом путь
   хранилища. Это прежний барьер побегов, только вместо записи в список —
   переезд.
3. Иначе — простая запись: молодой Box в своём регионе ничего не стоит.

Путь хранилища: место в карантине на два объекта; `rt_store_move(value)`;
счётчик нового +1; запись; счётчик старого −1, ноль — в карантин. Порядок
«сначала +1, потом −1»: `b.f = b.f` ничего не ломает.

Числа, `yes/no`, enum, `none` в поле — одно сравнение тега.

## Карантин и освобождение

Объект хранилища со счётчиком 0 не освобождается сразу: его может держать
локальная переменная (`@old = table.buckets; table.buckets = …; drum (old)`),
переменная вызывающего, значение `out`, объект живой кучи. Он попадает в
**карантин** (`memory/quarantine.saltic`, страницы записей «адрес, подсказка»).

При каждом выходе региона (`rt_region_exit`, в том числе в конце оборота
`always`) разбирается не больше `QUARANTINE_BATCH` (64) записей, по кругу от
курсора, чтобы никто не ждал вечно:

- счётчик стал больше нуля — запись снята;
- держатель есть — остаётся, с подсказкой «где нашли»: следующий раз одно
  сравнение. Держатели: значение `out`, слова стека от кадра выходящего навыка
  (у оборота — от текущего `STACK`: слоты навыка живы) до `rt_stack_base`, слова
  живой кучи `[heap_start, HEAP_TOP)` — не больше `QUARANTINE_HEAP_SCAN_WORDS`
  (65 536) слов, иначе объект считается удержанным (честно: освобождение
  откладывается, памяти не портит; у программ с большим корневым регионом —
  компилятор — освобождение из карантина пока не работает, это известный предел);
- иначе — освобождение: у детей счётчик −1, ноль — в карантин (место
  обеспечивается заранее; нет места — объект ждёт следующего выхода).

Проверка держателей консервативна: сырое слово, равное адресу, задержит
освобождение на один выход — не ошибка.

Внешняя переменная оборота `always`, которой тело присвоило значение из памяти
оборота, больше не держит оборот в куче: значение переезжает в хранилище
(`rt_store_keep`) и попадает в карантин — оборот убирается всегда. Константы
переезжают в хранилище навсегда (`rt_store_eternal`).

## Регион `drum` (15.11.2026)

`drum` открывает регион на весь цикл: `REGION_MARK = HEAP_TOP` на входе (метка
навыка — в слоте `$drum_mark:N`). Мусор оборотов (старые хвосты и узлы пути
`group.add`, строки шаблонов) не копится до выхода из навыка: в конце оборота,
когда занято больше, чем живое плюс `DRUM_SLACK_BYTES` (4 КБ; порог — в слоте
`$drum_limit:N`), регион сжимается тем же `rt_region_exit`, что и выход навыка:
корень — группа из значений внешних переменных, которым тело присваивает (кроме
фиксированных типов — их слово не отличить от указателя), живое копируется вниз к
`REGION_MARK`, остальное уходит. Порог после сжатия — удвоенное живое плюс запас,
так что копирования не больше двух байт на выделенный байт, а занято — не больше
двух живых плюс запас. Другие корни не нужны: Box старше региона при записи
указателя переезжает в хранилище (барьер), объекты хранилища на регион не
указывают, локальные тела к концу оборота мертвы. `out` и ошибка из тела — через
трамплины, возвращающие метку навыка перед общим выходом; `leave` — метка конца.
Код — `compiler/gorn/codegen/loops` (`region_open`, `region_close`, `region_restore`).

## Циклы ссылок запрещены (решение автора 14.11.2026)

Счётчик рёбер не обнулится у цикла, поэтому цикл — ошибка, не утечка:

- чекер (`checker/walk.saltic`, `check_cycles`) — на видимое в теле: `x.f = y`,
  где `x` достижим из `y` по литералам Box и групп, присваиваниям, чтению полей
  и прежним записям, — `cycle_reference`, текст «храни номер, а не объект»
  (канон `soul/canonical/checks/errors/cycles.saltic`);
- рантайм — при записи в хранилище: указатель на сам Box внутри перевозимого и
  цикл внутри перевезённого (Кан) — `CycleForbidden`; если у Box уже есть
  рёбра из хранилища — обход от нового значения (`memory/cycles.saltic`,
  `rt_cycle_reach`) не больше `CYCLE_BUDGET` (4096) объектов, строки и группы без
  Box не обходятся; нашли — `CycleForbidden`, не уложились — `CycleCheckExhausted`.
  Когда у Box рёбер из хранилища нет (`holder`, `compiler` — их держит слот),
  обход не нужен: цикл через него невозможен.

### Обходится только новое (решение автора 15.11.2026)

Запись `T.f = V`, когда у `T` есть рёбра из хранилища. Всё, что было достижимо из
старого значения `T.f`, к `T` не ведёт — иначе кольцо существовало бы до записи, а
колец в хранилище нет никогда (каждая запись проверена, исчерпание бюджета — ошибка,
не пропуск). Поэтому обход `V` не заходит в объекты, общие со старым значением:

- **старый фронт** — само старое значение и первые `CYCLE_FRONT` (32) его детей
  помечаются `STORE_MARK` до обхода (они в очереди, в счёте бюджета, метка снимается
  вместе с остальными). Это закрывает перестановки `group.add` у дерева групп:
  старый корень и старый хвост оказываются на новых местах (новый уровень, лист
  под корнем), но они — дети старого дерева;
- **тень** — обход идёт в ногу со старым значением: тень `V` — старое значение, тень
  ребёнка — слово той же позиции в тени родителя, если она того же вида (группа,
  дерево, Box) и позиция внутри её нагрузки (конец считается по `payload_bytes`, не
  по выровненному размеру). Ребёнок, равный слову тени, — старый, в очередь не идёт;
  иначе идёт пара (объект, слово тени). Очередь — пары, `CYCLE_BUDGET` пар.

Что обходится на деле: у плоской группы — добавленные элементы, у дерева групп —
путь до хвоста и новый элемент, у Box — изменившиеся поля. Новый элемент обходится
целиком (он и может вести к `T`): если он ссылается на старые элементы списка глубже
первого уровня, они обходятся как раньше. `group.replaced` у дерева даёт плоскую
группу другого вида — тени нет, обход полный (как было).

## Ограниченное худшее время

Каждая операция памяти — с границей: обход переноса — по размеру перевозимого,
разбор карантина — 64 записи за выход и каскад по кусочкам, проверка цикла —
4096 объектов (плюс сравнение слов по размеру самого нового объекта — он только что
скопирован переносом за ту же цену), поиск прогона — 64, сканирование кучи —
65 536 слов. Следующий
шаг — метроном (`METRONOME.md`): компилятор вставляет «жив» по худшему случаю.

## Стек

Навык в прологе сверяет `STACK` с `STACK_LIMIT`: ниже — честная ошибка
`StackExhausted` («стек исчерпан») вызывающему, не падение. На Linux программа
получает свой стек через `rt_platform_stack` (mmap без резерва: 1 ГБ на 8-байтном
слове, 64 МБ на 4-байтном; `STACK_LIMIT` — низ плюс 256 КБ запаса); где платформа
стека не даёт — стек входа и стража нет (`STACK_LIMIT = 0`).

## Нехватка памяти

Если объект не помещается — `MemoryExhausted` (номер 8, «память исчерпана»);
регион навыка освобождается, вызывающий ловит `rescue`. Код завершения 65 —
только до запуска `program`. Нехватка внутри `always` ловится так же: у оборота
нет корней вне региона, уборка оборота всегда удаётся.

## Что видно программе

`mem.heap(0)` — занято регионами, `mem.heap(1)` — байт страниц хранилища,
`mem.heap(2)` — квота, `mem.heap(3)` — записей в карантине.

## Ограничения

- Мусор `drum` между сжатиями лежит в регионе: занято до двух живых плюс 4 КБ;
  после последнего оборота остаток живёт до выхода из skill. У `always` свой
  регион на каждый оборот.
- Внешняя переменная фиксированного типа, которой присваивает тело `drum`, не
  корень сжатия: указателей в ней не бывает по правилу чекера (`fixed_escape`).
- Значения фиксированных типов runtime не отличает от указателей, поэтому
  чекер не выпускает их из локальных переменных навыка.
- Адреса, записанные через `mem.store_address32` в сырую память, не отслеживаются.
- Нехватка памяти прямо внутри вычисления константы оставляет константу в
  состоянии «вычисляется».
- Низ хранилища не поднимается обратно, свободные страницы ждут в карте;
  страниц у платформы (`rt_platform_pages`) пока нет — хранилище живёт внутри
  квоты (шаг 6 плана).
- Крупное значение в долгом поле каждый кадр — перенос каждый кадр; `bytes`
  меняются на месте и рождаются в хранилище — буфер создаётся один раз.
- Ключи с поколением (`StaleValue`, сжатие хранилища) — этап 2, по замерам.
