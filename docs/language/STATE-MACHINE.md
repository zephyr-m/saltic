# Конечный автомат Saltic

**Статус:** решение автора, записано 14.11.2026. Ядро языка и кодогена, не
библиотека и не только синтаксис. Делается первым, метроном
(`docs/language/METRONOME.md`) — следом (решение автора 15.11.2026): автомат задаёт
границы переходов, метроном встаёт на них. Почти последние шаги перед первым свистком.

## Два уровня

1. **Слово `machine`** — 16-е ключевое слово (решение автора 03.11.2026,
   `.archive/docs/PLAN-1.md`, «До заморозки синтаксиса»). Явная машина, каждое
   событие само становится её навыком:
   ```
   Door = machine {
       CLOSED { open => OPEN, lock => LOCKED }
       OPEN   { close => CLOSED }
       LOCKED { unlock => CLOSED }
   }

   @door = Door.CLOSED
   door = Door.open(door)       -- OPEN
   door = Door.unlock(door)     -- ошибка ForbiddenStep: из OPEN нельзя
   door = Door.opne(door)       -- ошибка чекера: у Door нет «opne»
   door = Door.LOCKED           -- ошибка чекера: состояние меняется только событием
   ```
   В обход перейти нельзя, опечатка в событии ловится при сборке, чекер видит
   тупики и недостижимые состояния.

2. **Автомат в кодогене — главное.** Автомат вшит в то, что выпускает
   компилятор. Каждая программа, включая ОС, работает внутри автомата
   автоматически, даже если разработчик слово `machine` не использует. Его
   получат все программы после пересборки, даже старые.

## Как именно — открыто

Механизм ещё не выбран. Оценка, не решение: компилятор режет программу в точках
остановки (отметка метронома, ожидание события, конец оборота `always`); кусок
между ними — состояние. Живые на границе переменные компилятор знает, значит
состояние программы — номер куска плюс эти переменные, обычные данные. Вся
программа становится одной функцией `шаг(состояние) → новое состояние`, а
каждая отметка «жив» метронома — переходом. Поэтому они делаются вместе.

Что из этого следует, если подтвердится:

- программу можно остановить на одном железе и продолжить на другом с той же
  точки — состояние передаётся как байты;
- ОС не выдёргивает программу посреди инструкции: управление отдаётся на
  границе состояния;
- сохранение всей системы и продолжение после выключения
  (`docs/os/OS-core.md`, «Предсказуемость»);
- воспроизведение такт в такт по записанным входам; «где сейчас программа» —
  номер состояния;
- конечное число состояний проще доказать (машина задуманного).

## Рекурсия

Рекурсия ограничена. Предел — пока, скорее всего, квота программы: кадры стека
лежат в квоте, переполнение стека — то же честное исчерпание памяти, а не немое
падение, и стек — часть состояния автомата. Точная глубина не решена.
Бесконечная рекурсия на практике не нужна.

## Открыто

- Где точки остановки и сколько их: только отметки метронома и ожидания или
  больше.
- Как сохраняется состояние: какие переменные, в каком виде, сколько стоит
  переход.
- Как `machine` из языка и автомат кодогена связаны: одна ли это машина.
- Предел рекурсии: квота или фиксированная глубина.
- Родные вызовы и внешние устройства: что входит в состояние, а что нет.
