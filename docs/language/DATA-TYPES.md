## Что значат незнакомые

- **Фиксированной ширины** — число ровно на 8, 16, 32 или 64 бита, как
  регистры железа. Нужно драйверам: `u8` — байт от 0 до 255.
- **Длинная арифметика** — числа любой длины без переполнения (`2^200`
  точно). Нужна для криптографии.
- **Кортеж** — несколько разных значений одной пачкой без имён полей:
  `(1, "а")`.
- **Перечисление с данными** — вариант, внутри которого свои значения:
  «Фигура» — либо `Круг(радиус)`, либо `Квадрат(сторона)`. Этим знаменит Rust.
- **Ошибка как значение** — ошибка возвращается как обычный результат, а не
  «выбрасывается». В Saltic — `error.Имя` и `rescue`.
- **Функция как значение** — функцию можно положить в переменную или
  передать другой функции: `x => x * 2`.
- **Обобщённые типы** — «список чего угодно» `Список<T>`: один код для
  списков чисел, строк и прочего.
- **Интерфейс** — договор «у типа есть метод `нарисовать`» без уточнения,
  какой это тип.

## Что видно по колонке Saltic

- Звенья (решение автора 21.11.2026; придуманы в апреле, когда подбирались слова
  языка): `○` — «и», один кружок на всех, нужны все; `○○` — «или», по кружку
  каждому, хватит любого. Счёт короткий: правое звено считается, только если
  левое не решило. Порядок — только скобками: сравнение рядом со звеном — в
  своих скобках, `○` и `○○` в одном ряду не смешиваются (ошибки разбора
  `comparison_needs_parens`, `links_mixed`), сцепляют только `yes/no`
  (`link_expects_answer`). Голое сравнение в остальном коде (`@x = a == b`) —
  нарушение `limits` (известные — `workbench/check/limits-parens.txt`, правятся
  потихоньку). В SalticIDE `&` набирает `○`.
- Сильное — то, что делает код простым: `yes/no`, `none`, ошибки по имени,
  `Box` с умолчаниями, один список — группа. Нет двух способов сделать одно.
- Объект виден разом (решение автора 19.11.2026): часть объекта — вложенный
  `Box` (`Car = Box { engine = Engine {} Engine = Box { … } }`). Снаружи часть
  создаётся полным именем `Car.Engine { … }`; в модуле видна и коротким
  `Engine`, если она одна такая (иначе `ambiguous_part`). Главный субъект
  модуля приходит из `use` без заикания: `use …agent.agent` даёт `Agent`.
- Нет совсем: функций как значений, обобщённых типов, кортежей.
  Дробные — плавающие (решение автора): `core.fraction` и матрицы
  `core.matrix`, только на 64-битных целях; с целым не смешиваются (явно
  `fraction.from(n)`), `==` у них нет — `~=` или `near`. 64-битные пришли с
  каноном RV64 (06.11.2026): на RV64, x86-64 и ARM64 обычное число 61-битное,
  на 32-битных платах — 29 бит. Словарь —
  модуль ядра `core.dict` без нового синтаксиса (решение автора 03.11.2026):
  `dict.new()`, `dict.set` меняет на месте, `dict.get` (`UnknownKey`, если
  ключа нет), `dict.has`; ключ — только строка.
- Особняком — фиксированные типы (`u8…usize`, `bits32`, `address`): создаются
  только через `тип.from(…)` с `use core.тип`; с шагом 3а они выходят в поля
  Box и результаты навыков (тип параметра чекер выводит из мест вызова, Q-001).
  С 19.11.2026 так же — у навыков субъекта, если вызов прямой (свой навык
  внутри Box или `x.навык(…)` у `x` известного Box). Если навык выбирается во
  время работы (тип хозяина неизвестен), фиксированное и дробное в него не
  уходят: `fixed_escape` / `fraction_escape` с причиной.
- PHP близок по духу: один `array` на всё — список, словарь, почти кортеж.
  Только PHP выбрал гибкость, а Saltic — простоту.
