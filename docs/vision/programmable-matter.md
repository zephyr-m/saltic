# Programmable Matter

Этот документ фиксирует дальний север S.

S существует не только для программ, окон, игр, роботов или симуляций.

Дальний целевой образ:

```text
S exists to command programmable matter.
```

## Главная мысль

Финальная цель — материя, которая может организовываться в полезные формы по намерению.

Не только:

```text
нарисуй стул на экране
```

А:

```text
соберись в стул
```

Не только:

```text
покажи модель костюма
```

А:

```text
обволоки тело как защитный костюм
```

В таком мире программа не просто выводит результат.

Она меняет организацию материи.

## Почему это важно уже сейчас

Мы не строим programmable matter сейчас.

Но язык, runtime, actor fabric и visual protocol должны с самого начала не закрывать путь к ней.

Ранние решения должны проходить фильтр:

```text
будет ли это работать, если объект состоит из миллионов локальных акторов?
```

Если ответ нет, решение подозрительно.

## Материя как сеть акторов

Финальная материя мыслится как огромная сеть маленьких участников:

```text
matter cell = actor
material = actor fabric
shape = coordinated actor state
object = stable pattern of matter
tool = temporary matter organization for a task
```

Это продолжает [Actor Fabric v0](../hardware/actor-fabric-v0.md).

Актор не является CPU.

Актор является участником физической организации.

## Путь уменьшения

Маршрут должен быть постепенным:

```text
S language
runtime / S Machine
actor fabric simulator
pixel actors
hardware actors
drone swarm
smaller physical actors
programmable matter
```

Первый актор может быть пикселем.

Следующий актор может быть узлом симуляции.

Физический актор может начаться как крупный модуль или коптер.

Наноразмер — дальняя цель, а не текущая инженерная задача.

## Роль visual

Рисование — это только первая видимая репетиция.

```text
visual trace -> pixel actors -> observed image
```

Но финальная цель шире:

```text
intent -> actor matter -> physical form
```

Поэтому `visual.*` не должен становиться центром архитектуры.

Он нужен как раннее наблюдение состояния и поведения.

## Роль языка

S должен уметь выражать:

- форму;
- состояние;
- локальное поведение;
- сообщения;
- соседство;
- время;
- локальный ритм;
- ограничения;
- безопасность;
- наблюдение;
- историю;
- намерение;
- проверку результата.

Команда `chair` в такой системе не является draw call.

Она должна означать набор проверяемых требований:

```text
intent: chair
constraints:
    supports human weight
    stable on floor
    safe contact surface
    height fits user
    stiffness is enough
    can disassemble after use
```

Команда `suit` ещё строже:

```text
intent: suit
constraints:
    follows body
    does not crush tissue
    supports movement
    protects from impact
    reacts fast enough
    fails safe
```

## Архитектурные запреты

Не строить S вокруг:

- центрального CPU;
- глобальной общей памяти;
- framebuffer как главной модели изображения;
- desktop OS;
- browser runtime;
- hidden mutation;
- непроверяемых команд к физической материи.

Эти модели могут быть временными backend.

Они не должны становиться каноном.

## Архитектурные опоры

Строить S вокруг:

```text
local state
local rule
message
neighbor
rhythm
formation
constraint
safety
history
observation
replay
```

## Безопасность

Programmable matter опаснее обычного софта.

Ошибка может стать физической травмой.

Поэтому будущая система должна иметь:

- ограничения до исполнения;
- симуляцию до физического действия;
- explain до действия;
- наблюдение после действия;
- history/replay;
- safe failure;
- границы силы, скорости, давления и температуры;
- человеческий override.

Это не v0, но это влияет на язык уже сейчас.

## Связь с цифровой бумагой

Цифровая бумага — это первый безопасный слой.

На ней можно:

- описывать форму;
- проверять ограничения;
- симулировать поведение;
- наблюдать историю;
- отправлять намерения акторам.

Позже тот же лист может стать планом физического действия.

```text
digital sheet -> simulated matter -> physical matter
```

## Практическое правило

Каждая большая фича S должна отвечать хотя бы на один вопрос:

- как это помогает описывать состояние материи?
- как это помогает локальному актору действовать?
- как это помогает сообщению между акторами?
- как это помогает наблюдать или проверять форму?
- как это помогает сделать действие безопасным?

Если фича не помогает ни одному из этих пунктов, она не является фундаментальной.
