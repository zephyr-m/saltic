# 3 ноября 2026: компилятор похудел в сорок раз

За одну ночь (с вечера 2 ноября до утра 3-го) вышли два релиза — 137:33
«Деревья» и 142:36 «Буфер». Компилятор Saltic стал собирать себя
в шесть раз быстрее и в сорок раз экономнее. А в конце оказалось, что
программы, написанные три недели назад, не просто пережили все эти
перестройки, а стали работать лучше.

Записано для учёбы: откуда взялся выигрыш и почему старый код не сломался.

## Цифры

| | вечер 2 ноября | утро 3 ноября |
|---|---|---|
| самосборка, время | 16,9 с | 2,9 с |
| самосборка, память | 1,19 ГБ | 28 МБ |
| компилятор под x86, сборка | ~650 МБ | 77 МБ |
| все тесты `global-check` | 37,7 с, 368 МБ | 19,1 с, 46 МБ |

## Откуда выигрыш

Ни одна правка не была хитрой оптимизацией. Каждая убирала лишнюю работу,
которую компилятор делал, потому что так было проще написать:

1. **Группы-деревья.** `group.add` копировал всю группу на каждое
   добавление. Теперь с 33-го элемента группа — дерево из узлов по 32, и
   копируется не больше 32 элементов на уровень.
2. **Баг имён.** Имена главной программы были видны из любого модуля и
   ломали чужие локальные переменные (`start` в программе ломал `start` в
   `core.str`). Чекер научился видеть голое имя только из главной программы.
3. **Таблица имён.** Каждый поиск глобального имени перебирал все ~2000
   имён. Теперь имена лежат в 64 корзинах по хешу — поиск идёт по ~30.
   Самосборка 9,5 → 4,1 с.
4. **Буфер байтов.** Каждый байт машинного кода был отдельным Box — 30–40
   байтов памяти на байт. Появился родной `core.bytes` (изменяемый, как Box,
   — решение автора), и компилятор хранит образ кусками по 4 КБ, где байт
   занимает байт. Самосборка 227 → 28 МБ.

Найти всё это помогли метрики тестов, добавленные в тот же вечер: пока
таблица не показала `machine — 365 МБ`, никто не знал, куда уходит память.
Не всё угадалось: разрезка большого теста почти не ускорила сборку, а
подозрение на чтение файлов по мегабайту замер опроверг — Linux не тратит
память на страницы, в которые ничего не записано.

## Старая программа запустилась — и стала лучше

Под утро автор запустил `just qemu-graphics` — ОС на RISC-V под QEMU с
программами, написанными 11–12 октября: лаунчер, змейка, пианино со звуком,
космос, задачи, типографика, колония. Почти 1 900 строк на Saltic за два дня
— тогда, когда самосборка занимала больше гигабайта, а баг имён заставлял
придумывать странные имена.

За три недели под этими программами поменялось почти всё: группы стали
деревьями, байты переехали в буфер, чекер иначе видит имена, комментарии
разрешены только в шапке, рантайм вырос, компилятор перестроился. А
программы просто запустились, как будто ничего не случилось. И работают
лучше: там, где они добавляли в группу, раньше копировалось всё целиком,
теперь — кусочек. Старый код бесплатно получил новую скорость.

Это не везение, а то, как строится язык: каждая правка проходит канон,
самосборку и тесты, а синтаксис почти не меняется. Заморозка — это
синтаксис: внутренности переворачиваются как угодно, код снаружи этого не
замечает.

## Saltic среди других

`fib(35)` на i5-12450H, лучшее из пяти запусков: C -O2 0,01 с, C -O0
0,05 с, Node 0,08 с, PHP с JIT 0,11 с, **Saltic 0,20 с**, PHP без JIT
0,31 с, Python 0,81 с. Языку пять месяцев (первые заметки — 24 мая 2026),
и он обгоняет PHP без JIT в полтора раза, а Python — вчетверо.

Ключевых слов у Saltic 14 (у Lua 22, у Go 25, у C 32): условие и цикл
обходятся без слов `if`, `while`, `end` — `(x) { … }`, `pick`, `drum`.

## Ещё за ночь

- `io.file.write_bytes` больше не обрезает 259 до 3 — ошибка
  `ByteOutsideRange`.
- Метрики тестов и паспорт компилятора: время, процессор, пик памяти,
  «было / стало» — и смайлики в выводе `global-check`.
- Аудит языка на согласованность и DRY — `docs/history/2026-11-02-audit.md`.
- WIRE проработал больше двух часов без единого сбоя (до починки падал на
  6-й минуте).
- WIRE падал от снимка экрана: `shot` клал снимок в арену с 64 КБ до
  ~852 КБ, а WIRE держал там же (с 256 КБ) кэш точек фигур — снимок затирал
  координаты, и на следующем кадре программа выходила с кодом 2. Кэш
  переехал на 1 МБ; на Acer — шесть снимков подряд посреди игры с фигурами,
  WIRE жив.
