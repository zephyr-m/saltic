# Философия

S — системный язык для автономной разработки, агентного программирования и будущего собственного железа.

Он нужен не для того, чтобы быть модным языком. Он нужен, чтобы заменить C там, где C слишком старый, слишком шумный и слишком дорогой по человеческой памяти.

## Главная идея

S должен быть языком, который можно восстановить из головы.

Обычный код должен писаться без интернета, без справочника под рукой и без постоянного вспоминания редких конструкций.

Если человек может легко писать на S, агент тем более справится.

## Для кого S

S проектируется для:

- человека, который хочет писать системный код без лишнего синтаксического шума;
- агентов, которым нужен строгий и маловариативный язык;
- собственного железа и собственной архитектуры;
- firmware, runtime, системных сервисов, инструментов и инфраструктуры;
- автономной разработки в условиях, где интернет может быть недоступен.

## Не цель

S не стремится быть языком с максимальным количеством возможностей.

S не должен предлагать десять способов сделать одну и ту же вещь.

S не должен требовать знания огромной стандартной культуры, как C/C++.

## Цель

S должен уменьшать:

- нагрузку на память человека;
- количество решений для агента;
- неоднозначность синтаксиса;
- количество скрытого поведения;
- стоимость написания низкоуровневого кода.

## Принципы

- **Автономность:** обычные задачи должны решаться без интернета.
- **Один очевидный путь:** базовые конструкции не должны иметь много равнозначных форм.
- **Ясность:** код должен быть читаемым без расшифровки.
- **Безопасность:** опасные действия должны быть явными.
- **Производительность:** язык должен подходить для системного кода и железа.
- **Детерминизм:** поведение должно быть предсказуемым.
- **Модульность:** экосистема делится на слои.
- **Toolchain-first:** Rocket является частью идеи языка, а не внешней утилитой.

## Zig как отправная точка

Zig выбран как инженерная база для размышления, потому что он уже близок к роли замены C.

Но S не должен быть просто Zig с другими словами. S должен быть уже, строже и удобнее для автономной разработки и агентной генерации кода.

## Слои экосистемы

S проектируется слоями:

- **L1 Kernel:** runtime, память, планировщик, агенты, безопасность.
- **L2 Std:** ввод/вывод, файлы, время, математика, строки, сеть, процессы.
- **L3 Core:** формализованные доменные ядра: математика, физика, химия, биология, логика и другие области.
- **L4 Packages:** внешние пакеты и прикладные расширения.

Зависимости идут только вверх.

## Главная проверка дизайна

Перед добавлением новой конструкции нужно спросить:

```text
Помогает ли это писать без интернета?
Уменьшает ли это выбор для агента?
Можно ли объяснить это коротко?
```

Если нет, конструкция не должна попадать в ядро языка.
