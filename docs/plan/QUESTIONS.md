## Q-049. `machine.word` → `u32`: слово в поле Box на rv32i

**К чему:** PLAN 3, «`machine.word` → `u32`»; Q-035 (вариант Г).

Слово машины живёт не только в переменных: оно лежит в полях Box
(`wide.Wide { low, high }`, адреса сегментов в `image`, `elf64`, `platform`,
`decoder.word`) и в группах команд. По Г фиксированное в поле и группе
упаковывается в обычное число, а на rv32i оно 29-битное: адрес `0x80000000` или
код команды с поднятыми старшими битами дадут `FixedTooBig`. Компилятор при
самосборке полки работает и на rv32i (третья сверка) — он упадёт.

- **А. Не переводить сейчас:** `machine.word` остаётся Box из четырёх байтов,
  пока не решён вопрос 32-битных плат (Q-035: «с 32-битными автор разберётся
  позже»).
- **Б. Перевести только арифметику:** внутри `word` считать в `u32`
  (переменные, параметры, `out`), а хранить по-прежнему байтами — уходит часть
  ручных переносов, раскладка не меняется.
- **В. Компилятору — только 64-битные хозяева:** убрать самосборку под rv32i
  из полки (rv32i остаётся целью, но не хозяином компилятора), тогда `u32` в
  полях влезает в 61 бит.

**Рекомендация:** Б сейчас; В — отдельным решением, когда 32-битным платам
не нужен будет свой компилятор на борту.

## Q-001. Откуда тип параметра

**К чему:** 64-битные числа, путь 3, шаг 3а —
[RECON.md](RECON.md#3а-фиксированные-типы-выходят-из-навыка--04112026);
[PLAN-1](../../.archive/docs/PLAN-1.md), «Типы у параметров и результатов навыков» (решение
автора 03.11: чекер выводит типы сам, без подписей).

Чекер должен знать, что параметр `p` — `u32`, иначе выберет не ту арифметику.

- **Из мест вызова.** Тип параметра — тип того, что передают во всех
  вызовах; разные типы (то `u32`, то число) — ошибка. Требует обхода графа
  вызовов до неподвижной точки.
- **Из тела.** Тип — по тому, как параметр используют. Слабее: `out p` или
  передача дальше о типе ничего не говорят.

**Рекомендация:** из мест вызова, у параметра один тип; в ошибке — откуда
пришёл тип.
