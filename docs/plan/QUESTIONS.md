## Q-048. Ветка сопоставления и переименование родных навыков

**К чему:** PLAN 3, пункты Q-017, Q-018, Q-019, Q-021, Q-022, Q-025.

1. **Что можно после `=>`** (Q-017: «вызов, присваивание, `out`»). Сейчас
   парсер берёт там одно выражение. Нужен разбор инструкции: одна инструкция
   (`.RED => color = 1`, `.RED => out "стоп"`) — или ещё и блок
   `.RED => { … }` для нескольких? И как сказать «ничего» для варианта, где
   делать нечего (Q-018 требует перечислить все варианты, а голое `none` после
   `=>` Q-017 запрещает) — `.OFF => { }`?
2. **Родные навыки меняют имена** (Q-019 `write_raw_bytes`/`write_buffer`,
   Q-021 `make`/`load`/`store`/`copy`, Q-022 `bits32.not` → `invert`) и
   **`-x`** (Q-025, 190 мест `0 - x`). Исходник компилятора собирает прежняя
   полка — она знает только старые имена и не понимает `-x`. Предлагаю два
   шага: (а) добавить новые имена и `-x`, старые оставить, перевести всё, кроме
   исходника компилятора; выпуск полки; (б) перевести компилятор и убрать
   старые имена. Так?

**Рекомендация:** 1 — одна инструкция или блок `{ … }`, «ничего» — `{ }`;
2 — два шага.

## Q-001. Откуда тип параметра

**К чему:** 64-битные числа, путь 3, шаг 3а —
[RECON.md](RECON.md#3а-фиксированные-типы-выходят-из-навыка--04112026);
[PLAN-1](../../.archive/docs/PLAN-1.md), «Типы у параметров и результатов навыков» (решение
автора 03.11: чекер выводит типы сам, без подписей).

Чекер должен знать, что параметр `p` — `u32`, иначе выберет не ту арифметику.

- **Из мест вызова.** Тип параметра — тип того, что передают во всех
  вызовах; разные типы (то `u32`, то число) — ошибка. Требует обхода графа
  вызовов до неподвижной точки.
- **Из тела.** Тип — по тому, как параметр используют. Слабее: `out p` или
  передача дальше о типе ничего не говорят.

**Рекомендация:** из мест вызова, у параметра один тип; в ошибке — откуда
пришёл тип.
