[PLAN-1](../../.archive/docs/PLAN-1.md), раздел указан у ответа.

## Q-042. Фиксированное в общем навыке библиотеки

**К чему:** PLAN 3, 3а — `group.contains(items, u32.from(2))` делал параметр
`core.group.contains` типом u32, ошибки всплывали в чужом коде.

**Ответ 11.11.2026:** новый вариант, одно правило для всех навыков (без
особого случая `core.*`/`craft.*`): параметр получает фиксированный тип, только
если все места вызова передают туда один и тот же фиксированный тип. Вызовы
разные — параметр обычный, а фиксированное в таком вызове кодоген упаковывает
в число (`rt_fixed_pack`, как в поле Box и группе; на 32-битных не влезло —
`FixedTooBig`). Ошибки «строка там, где u32» внутри чужого навыка быть не
должно. Смешение внутри такого навыка обычного параметра с фиксированным —
Q-037 на строке внутри навыка. Про `out` с фиксированным и обычным из разных
мест — подумать, неоднозначно — спросить. Заодно: `result_falls_through`
(навык с фиксированным результатом кончается `out`) — оставить.

## Q-041. Дробные: что решить до кода

**К чему:** PLAN 3, «Дробные»; Q-008, Q-014, Q-038.

**Ответ 11.11.2026:** все пять — А. 1 — дробное рядом с целым (`1.5 * 2`) —
ошибка чекера, явно `fraction.from(count)`. 2 — `fraction.from(n)`; обратно
`num.round` (к ближайшему), `num.floor`, `num.ceil`, `num.trunc`. 3 — показ
(`io.show`, подстановка) — кратчайшая запись, которая читается обратно точно
(`0.30000000000000004`, `2.5`); красивый вывод — отдельный навык вроде
`fraction.text(x, digits)`. 4 — `~=` — относительная точность, `NEAR = 1e-9`;
`==` на дробных — ошибка; свой порог — навык вроде `fraction.near(a, b, eps)`.
5 — три младших бита (литерал и результаты) — округлять до ближайшего. На
32-битных платах дробные — ошибка сборки (Q-038).

## Q-038. Дробные: какая метка и что на 32-битных

**К чему:** PLAN 3, «Дробные»; Q-014 — все восемь меток были заняты.

**Ответ 11.11.2026:** `yes`/`no` и `none` делят одну метку «малые

## Q-037. Фиксированный рядом со значением неизвестного типа

**К чему:** PLAN 3, 3а, Q-002 — `u32.from(1) + p`, где тип `p` не выведен.

**Ответ 11.11.2026:** ошибка чекера — арифметика, сравнение и `==`

сделай u32.from(…)».

## Q-036. 3а: группа фиксированных и core.group

**Ответ 11.11.2026:** вариант Г, общий с Q-035 — сырых групп нет:
фиксированное в группе (литерал, `group.add`) упаковывается в обычное
число. `core.group` не меняется.

## Q-035. 3а: поле Box фиксированного типа и Box неизвестного типа

**К чему:** PLAN 3, 3а (шаг 2) — тип Box у параметра чекер не знает, сырое
поле прочлось бы как обычное число.

**Ответ 11.11.2026:** вариант Г (новый) — фиксированных полей и групп как
отдельного вида нет. Фиксированное, положенное в поле Box или группу
(конструктор Box, значение по умолчанию поля, присваивание поля, литерал
группы, `group.add`), язык сам упаковывает в обычное число (NUMBER);
читается оттуда обычное число, снова фиксированное — явно `u16.from(…)`.
Признак «сырое» сборщику не нужен, вывод Box-типов параметров не нужен —
автор сознательно уходит от строгой типизации. Голые биты живут только в
переменных, параметрах, `out` и буферах (`bytes`, будущие `words`). На
32-битных платах значение больше обычного числа (29 бит) — пока ошибка при
запуске `FixedTooBig`.

## Q-034. Остаток от деления: оператор или навык

**Ответ 07.11.2026:** оператор `%` в языке — приоритет как у `*` и `/`, знак остатка — как у делимого; для фиксированных типов пока ошибка `fixed_remainder`. `num.mod` и формулы `x - x / d * d` заменены, `num.mod` — в архив. Заодно: граница обычного числа — одна, `num.MAXIMUM`, на неё опираются `abi`, счётчик `core.time` и ожидание звука ОС. → PLAN, раздел 8

## Q-028. Программа выше 4 ГБ на x86-64

**К чему:** куча больше 4 ГБ на x86-64 упирается в образ: строки программы
лежат после кучи, адреса меток — 32-битные (ABS32). → PLAN 7, пункт 1

**Ответ 07.11.2026:** строки — до кучи, куча — последней в образе и растёт

## Q-027. Выход компилятора без права исполнения

**К чему:** компилятор пишет ELF без бита исполнения, `chmod +x` делают 8
скриптов. → PLAN 5, аудит 03.11, 4.4

**Ответ 07.11.2026:** компилятор сам ставит бит исполнения на ELF для Linux

## Q-026. Проверка тега, пока чекер не выводит типы

**К чему:** `plus_one("abc")` → `""`: параметр без типа, `+` складывает слова
без проверки тега. → PLAN 5, аудит 03.11, топ-1

**Ответ 07.11.2026:** проверка в рантайме только там, где чекер тип не знает:
`+ - * / < >` смотрят тег и на не-числе бросают `TypeMismatch`. Где тип
известен — без проверки. Уходит вместе с выводом типов (3а).

## Q-002. Литерал рядом с фиксированным

**К чему:** писать `p + 24` вместо `p + u32.from(24)` — голый литерал брал
бы тип фиксированного соседа. → PLAN 3 (3а), RECON «3а»

**Ответ 07.11.2026:** нет — всегда явно: `p + u32.from(24)`. Литерал рядом с
фиксированным типом сам тип не берёт.

## Q-025. Отрицание `-value`

**К чему:** минус есть только у литерала (`-100`); перед именем и выражением
пишут `0 - value` (190 мест). → PLAN 4, аудит 02.11, «Язык в бою», 3

**Ответ 07.11.2026:** унарный минус у любого выражения: `-speed`,
`-(a + b)`, `-group.count(items)`. Чтобы способ был один, места `0 - x`
переводятся на `-x` (механика). Голое выражение на своей строке (`-1` после
переноса) — ошибка чекера «выражение без действия».

## Q-024. Битовые операции у обычных чисел

**К чему:** биты умеет только `bits32`, его нельзя смешивать с числами;
драйверы проверяют биты регистров делением и остатком (`has_bit`). → PLAN 4,
PLAN-1 «Опыт в бою», 3

**Ответ 07.11.2026:** навыки в `core.num` для обычных чисел: `num.and`,
`num.or`, `num.xor`, `num.shift_left`, `num.shift_right`, `num.bit(value, n)`
-> yes/no. Операторов `& | ^ << >>` в синтаксисе нет; `bits32` остаётся для
точной 32-битной работы.

## Q-022. Имена: `bits32.not` и названия ошибок

**К чему:** `bits32.not` — единственное `not` в языке без отрицания;
ошибки `…OutOfRange` и `…OutsideRange`, `Bad…` и `Invalid…`. → PLAN 4,
аудит 02.11, А15

**Ответ 07.11.2026:** `bits32.not` → `bits32.invert`; `PatchOutOfRange`,
`OperandOutOfRange` → `…OutsideRange`; `Bad…` → `Invalid…`. В канон —
словарик имён ошибок: «вне диапазона» — `…OutsideRange`, «неверный» —

## Q-021. `core.bytes` — один набор

**К чему:** два набора имён — родные `make/load/store/copy` без проверок
(`store(b, 0, 300)` молча кладёт 44, ошибка — чужая `StringBounds`) и
обёртки `new/get/set/slice` с проверками. → PLAN 4, аудит 03.11, 2.1

**Ответ 07.11.2026:** один набор `new` / `count` / `get` / `set` / `slice`;
проверки — в рантайме `rt_bytes_*` (свои `BytesBounds`, `ByteOutsideRange`).
Обёртки на Saltic и имена `make` / `load` / `store` / `copy` — в архив, прямые
вызовы переходят на `get` / `set`.

## Q-020. Строки — байты или буквы

**К чему:** `str.get` / `slice` / `upper` / `lower` работают по байтам —
кириллица рвётся и не меняет регистр. → PLAN 4, аудит 03.11, 2.4

**Ответ 07.11.2026:** `str.get` и `str.slice` остаются байтовыми (индексы в
байтах; компилятор и сеть не замедляются) — шапка `str` говорит это честно.
Для букв — свои навыки: `str.letters(text)` -> группа букв за один проход,
`str.letter(text, index)` -> буква. `str.upper` / `str.lower` знают кириллицу.

## Q-019. Словарь глаголов ядра

**К чему:** шесть имён на запись и чтение файла; `num.digit(ch)` и
`num.hex_digit(value)` — противоположные направления; `bytes.read_u16`
работает со строкой. → PLAN 4, аудит 03.11, 2.2, 2.3

**Ответ 07.11.2026:** поправить только путающее. Файлы — четыре имени:
`read` / `write` — текст, `read_bytes` / `write_bytes` — буфер `core.bytes`
(группа чисел — через `bytes.from_group`; `write_raw_bytes` и `write_buffer`
уходят). Цифры — направление в имени: `num.digit_value(ch)`,
`num.hex_value(ch)`, `num.hex_char(value)`. `bytes.read_u16` → `str.read_u16`.
Полный словарь по одному образцу — не делаем.

## Q-018. Неполное сопоставление enum и `pick` без умолчания

**К чему:** сопоставление без одного варианта и `pick` без ветки по
умолчанию молчат. → PLAN 4, аудит 03.11, 3.2

**Ответ 07.11.2026:** сопоставление обязано перечислить все варианты enum —
иначе ошибка чекера `switch_incomplete` с недостающими вариантами. `pick`
остаётся как есть: «первое подходящее условие», ничего не сделать — законный
исход.

## Q-017. Значение блока и сопоставление enum

**К чему:** в сопоставлении `.RED => "стоп"` значение молча выбрасывается;
хвостовое значение есть только у `rescue`; `(x) { … }` — условие или
сопоставление по телу. → PLAN 4, аудит 03.11, 1.3; аудит 02.11, А6, А7

**Ответ 07.11.2026:** сопоставление — оператор. Ветка `=>` выполняет код
(вызов, присваивание, `out`); голое значение после `=>` — ошибка чекера.
Значение выходит из навыка только через `out`; хвостовое значение — только у
`rescue`. Форма `(x) { … }` для условия и сопоставления остаётся одной
(«разобрать значение»).

## Q-016. Условие принимает любой тип

**К чему:** `("text") { … }` и `(7) { … }` — истина, `(0) { … }` — ложь по
совпадению устройства в памяти, `([])` — истина; чекер молчит. → PLAN 4,
аудит 03.11, 1.2

**Ответ 07.11.2026:** в условии — только `yes`/`no`. Иной тип — ошибка
чекера `condition_type`; значение, чей тип чекер пока не знает, пропускается
до вывода типов (3а).

## Q-015. Варианты enum — одно имя на всю программу

**К чему:** `READY` нельзя завести в двух enum, даже в разных модулях
(`duplicate_enum_variant`), потому что короткая запись `.READY` ищется по
голому имени. → PLAN 4, аудит 03.11, 1.1

**Ответ 07.11.2026:** вариант принадлежит своему enum. Полное имя —
`State.READY`; короткое `.READY` — только в ветках сопоставления, где enum
понятен по значению; вне сопоставления `.READY` — ошибка чекера. Один и тот
же `READY` может быть у разных enum.

## Q-014. Как дробное число живёт в слове с меткой

Обычное значение — 64-битное слово с 3 битами метки, а `double` занимает
все 64 бита. Варианты были: сырое значение как у фиксированных типов
(ждёт 3а), объект в куче на каждое значение (медленно), урезанная
плавающая.

**Ответ 06.11.2026:** урезанная плавающая — 61 бит: `double` без трёх
младших битов мантиссы, на их месте метка. Около 15 десятичных знаков
вместо 16; дробные — обычные значения (группы, поля, параметры, `out`) без
3а. Заодно закрыто противоречие в прежнем плане: вид дробных — плавающие.
32-битные платы — отдельный вопрос.
