# Group v0

`Group` — конечная группа значений.

Он нужен, чтобы на цифровой бумаге можно было описать несколько вещей без перехода к системным массивам, layout памяти или динамическим коллекциям.

## Назначение

`Group` должен:

- описывать группу объектов, действий, измерений или параметров;
- сохранять порядок записи для детерминированного обхода;
- работать вместе с `drum`;
- не превращаться в `Array`, `List` или `Set` из других языков.

## Создание

```s
@objects = [
    Object { name = "PLAYER" },
    Object { name = "LIGHT" },
    Object { name = "WALL" },
]
```

Пустая группа:

```s
@items = []
```

Пустая группа внутри `Box` может быть использована как пустой group-слот:

```s
Point = Box {
    x = 0
    y = 0
}

Shape = Box {
    points = []
}

@points = [
    Point { x = 1 y = 2 },
    Point { x = 3 y = 4 },
]

@shape = Shape {
    points = points
}
```

`[]` не задаёт отдельный новый синтаксис типов. В v0 это означает: поле ожидает `Group`, а конкретный тип элементов приходит из значения, которое кладётся в поле.

## Обход

`Group v0` не вводит отдельный цикл.

Если нужен индекс, он пишется явно:

```s
@index = 0
drum (core.group.count(objects)) {
    @object = core.group.at(objects, index)
    index = index + 1
}
```

Это сохраняет одну форму повторения: `drum`.

## std

Минимальная поверхность:

```s
core.group.count(group)
core.group.at(group, index)
```

`index` в v0 начинается с `0`.

## Не входит в v0

- изменение элемента;
- добавление и удаление элементов;
- сортировка;
- поиск;
- map/filter/reduce;
- уникальность элементов;
- memory layout;
- capacity;
- slices;
- pointer/buffer semantics;
- отдельная форма `each`.

## Открытые вопросы

- Нужен ли позже системный `Array` отдельно от `Group`.
- Как `Group` будет связан с памятью и ABI.
- Должен ли `Group` требовать одинаковый тип элементов или разрешать смешанные группы.
- Нужна ли отдельная форма обновления группы.
