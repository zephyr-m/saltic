# Runtime

Этот документ описывает runtime-модель S.

Сейчас реализация живёт в Racket bootstrap и исполняет текущий `v0.1` срез. Долгосрочно это становится слоем L1 Kernel.

## Зачем нужен runtime

S должен жить на собственном железе и собственной архитектуре. Поэтому runtime не может быть случайным набором библиотек. Он должен быть частью модели языка.

Runtime должен быть достаточно маленьким, чтобы его можно было портировать и понимать без интернета.

## Time

Для физической ветки S время не должно быть обычной библиотечной функцией.

Время является свойством среды исполнения:

```text
state -> input -> transition -> next state -> observation
```

Runtime/engine отвечает за порядок переходов, history и воспроизводимость.

Пользовательский код описывает состояния и правила перехода, но не обязан вручную считать время, если программа исполняется внутри среды.

Объекты могут иметь локальный ритм относительно времени среды. Это коэффициент локального времени объекта к времени среды, а не отдельный счётчик тиков.

Подробнее: [Time and State v0](time-state-v0.md).

## Черновой состав L1

L1 может включать:

- старт программы;
- память;
- планировщик;
- agent VM;
- базовую безопасность;
- границы процессов/агентов;
- логирование ошибок;
- hooks для детерминированного исполнения.

## Контракт слоёв

Нижний слой не зависит от верхнего.

```text
L4 Packages
    зависит от L3
L3 Core
    зависит от L2
L2 Std
    зависит от L1
L1 Kernel
    не зависит от верхних слоёв
```

## Текущий срез

Сейчас runtime поддерживает первый исполняемый подмножество языка:

- `program(...)`;
- `skill`;
- `out`;
- переменные и присваивания;
- `if`;
- `switch`;
- `drum`;
- `rescue`;
- вызовы `host.*` и `world.*` из bootstrap.
