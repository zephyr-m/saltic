# Типы

S использует вывод типов по умолчанию, но должен оставлять возможность явной записи там, где это нужно для системного кода.

## Вывод типа

Первое присваивание фиксирует тип.

```s
@x = 10
x = 20
```

Позднее присваивание несовместимого типа должно быть ошибкой проверки.

## None

`none` — маркер пустого значения.

```s
@value = none
```

Связь между `none`, optional-значениями и `Box` ещё требует точного определения.

## Yes/No

`yes` и `no` — значения ответа.

```s
@visible = yes
@blocked = no
```

Сравнения и проверки возвращают `yes` или `no`.

```s
@safe = charge > min
core.io.println(safe)
```

В S для ответа используются только `yes` и `no`.

## Box

`Box` — основная идея структурированного контейнера данных.

Текущий канон формы описан отдельно: [Box v0](box-v0.md).

Для физической модели `Box` трактуется как форма состояния в моменте, а не как вся вещь с identity во времени. См. [Time and State v0](time-state-v0.md).

В текущей реализации `Box v0` поддерживает объявление формы, создание значения с defaults и доступ к полям через точку.

```s
Player = Box {
    name = ""
    hp = 100
    inventory = none
}

@player = Player {
    name = "Zephyr"
    hp = 999
}
```

`Box` должен уменьшать количество решений для человека и агента. Он не должен превращаться в сложную объектную систему.

Открытые вопросы:

- заменяет ли `Box` все структуры;
- какие у `Box` семантики: value, reference или обе;
- как `Box` связан с identity-object и временем;
- как `none` работает внутри полей;
- как задаются layout, alignment и ABI для низкоуровневого кода.

## Group

`Group` — конечная группа значений.

Текущий канон формы описан отдельно: [Group v0](group-v0.md).

```s
@objects = [
    Object { name = "PLAYER" },
    Object { name = "LIGHT" },
    Object { name = "WALL" },
]
```

`Group v0` сохраняет порядок записи для детерминированного обхода через `drum`.

```s
@index = 0
drum (core.group.count(objects)) {
    @object = core.group.at(objects, index)
    index = index + 1
}
```

`Group` не является системным `Array`. Layout памяти, capacity, slices и pointer semantics остаются отдельным будущим решением.

## Enum

```s
Status = enum {
    OK,
    ERROR,
    PENDING,
}
```

## Что не входит в v0

В активном каноне S пока нет отдельных конструкций для `union`, typed
declarations, системных массивов, slices и указателей.

Это не скрытые возможности и не альтернативные способы записи. Их нотация и
семантика ещё не утверждены, поэтому они не должны появляться в обычных
примерах и спецификациях v0. `Group v0` — единственная текущая форма группы
значений.

Будущая системная модель памяти появится только после отдельного решения о
том, какие из этих понятий действительно нужны и нельзя ли выразить их уже
существующими формами.
