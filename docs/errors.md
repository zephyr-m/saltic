# Ошибки

S считает ошибки обычной частью поведения программы.

Цель: сделать error flow явным, но не заставлять человека помнить сложную систему исключений.

## Возврат ошибки

Любая функция может вернуть ошибку.

```s
skill divide(a, b) {
    (b == 0) {
        out error.DivisionByZero
    }

    out a / b
}
```

В текущем черновике нет маркера `!`.

## Rescue

`rescue` обрабатывает ошибку локально.

```s
@safe = divide(10, 0) rescue |err| {
    std.io.println("division failed")
    0
}
```

Блок `rescue` возвращает fallback-значение.

## Try

`try` пробрасывает ошибку выше.

```s
@value = try divide(10, 0)
```

Точный синтаксис `try` ещё открыт.

## Необработанные ошибки

Необработанные ошибки автоматически логируются.

Черновое поведение:

- запись в `yametekudasai.log`;
- имя файла;
- строка;
- ошибка;
- финальная строка `Yametekudasai xN` со счётчиком ошибок.

Идея запоминающаяся, но её нужно аккуратно разделить на режимы:

- debug/development;
- production;
- embedded/no filesystem.

Для железа и агентов поведение ошибок должно быть детерминированным. На раннем этапе это поведение можно проверять внутри Racket-реализации, а позже перенести в runtime/backend S.
