# Скорость Saltic среди других языков

Сравнительная таблица по задачам из The Computer Language Benchmarks Game и
рекурсивному fib. Каждая задача написана одним алгоритмом на всех языках,
вывод сверен с C байт в байт. Когда у Saltic появится новый бэкенд (родной
x86-64, RV64…), он добавляется отдельной строкой «Saltic, <бэкенд>» — старые
строки не стираются, чтобы был виден путь.

## Как мерили

Исходники всех задач на всех языках — `docs/benchmarks/` (`fib.*`,
`binary-trees.*`, `fannkuch.*`), ожидаемый вывод — `*.expected`.

- Машина: Acer, Intel Core i5-12450H, NixOS; один поток.
- Время — лучшее из 3 запусков (`/run/current-system/sw/bin/time`, `%e`),
  память — пик RSS (`%M`).
- Saltic собран компилятором с полки, цель `x86_64` (машинный код RV32I,
  переведённый в x86-64); «Saltic, QEMU» — тот же RV32I под `qemu-riscv32`.
- Языки: C — GCC 14.3 (`-O2`, `-O0`); Node 24.18; PHP 8.4.22 (JIT —
  `opcache.jit=tracing`); Lua 5.4.9; LuaJIT 2.1; Ruby 3.4.11 (YJIT —
  `--yjit`); Python 3.13.12.

## Что видно

- **Память** — у Saltic лучшая или почти лучшая везде: 9 МБ на
  binary-trees против 47–108 МБ у интерпретаторов и JIT, меньше 1 МБ на
  fannkuch (массивы на `core.bytes`).
- **Вызовы и арифметика** (fib) — Saltic обгоняет все обычные
  интерпретаторы; впереди языки с JIT и C.
- **Массивы** (fannkuch) — на уровне Lua 5.4, чуть медленнее PHP, втрое
  быстрее Ruby, в семь раз быстрее Python.
- **Мелкие объекты** (binary-trees) — слабое место: последнее место, в 20 раз
  медленнее C. Каждая группа из двух элементов — выделение памяти, регион,
  проверки. Сюда смотреть первым на этапе оптимизаций (`docs/PLAN.md`,
  «Скорость»: анализ побега, встраивание, дешёвое выделение).

Ждут дробных чисел: n-body, spectral-norm, mandelbrot.
