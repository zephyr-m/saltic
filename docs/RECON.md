## Память в `always` — 06.11.2026

**Сделано 06.11.2026, вариант 2** — итог в [PLAN.md](PLAN.md), «Баги».

К чему: [PLAN.md](PLAN.md), «Баги» — «Вечный цикл не отпускает память
регионов».

- **Как сейчас.** Регион — на вызов навыка: вход запоминает `REGION_MARK`,
  выход (`rt_region_exit`) освобождает всё сверху и поднимает результат в
  регион вызвавшего. У циклов (`always`, `drum`) своего региона нет.
- **Замер** (x86-64, куча 1 МБ): Box из трёх полей, полученный вызовом прямо
  в теле `always`, — ~48 байт за оборот, память кончается на ~21 500-м.
  Тот же вызов внутри навыка-«тика» — 20 млн оборотов без роста.
- **Кто течёт.** Агент — нет (`always { survive(agent) }`, `survive` отдаёт
  `none`). Текут циклы, где результат вызова кладётся прямо в теле:
  ожидание Esc в raytrace (`@key = uefi.poll_key(base, PAUSE)`, пауза 5 мс) и
  два цикла jumper, драйвер клавиатуры и `os/main` старой ОС. На глаз —
  десятки КБ в секунду простоя, программа на Acer упрётся в кучу за час-два.
- **Обход** — тело в навык (`tick`), как у агента: 30–60 строк в 4–5 файлах.
- **Настоящее решение** — регион на оборот `always`: метка в начале
  оборота, в конце — `rt_region_exit` без значения, но с корнями-слотами
  внешних переменных, в которые пишет тело (их список чекер уже собирает,
  `collect_block_names`); `out` и `leave` из тела сначала возвращают метку
  навыка. Рантайм общий для обоих бэкендов. Прогноз 250–400 строк с тестами;
  риск — корни-слоты: сейчас корень у выхода один (результат) плюс записи в
  старые объекты через барьер.

## 3а: фиксированные типы выходят из навыка — 04.11.2026

Часть 64-битных чисел, путь 3 (выбран автором 04.11.2026; полная разведка —
[fable/2026-11-03-64bit.md](fable/2026-11-03-64bit.md)). Сейчас `u8`…`usize`,
`bits32`, `address` живут только в локальных переменных: в параметр, `out`,
поле Box и группу чекер их не пускает («там фиксированный тип теряется»).

**Прогноз: 600–750 строк в компиляторе**, затем отдельным шагом переезд ОС
на `u32`/`address` — минус 200–250 строк (`hi/lo` и `Phys { hi, lo }`: 176
строк в 31 файле). Разведка 03.11 давала 400–500; выше — из-за родного
x86-бэкенда и честного счёта сборщика.

| Часть | Строк | Что |
|---|---|---|
| Вывод типов, чекер | 300–400 | поля Box — из значения по умолчанию (~40); результат навыка — из `out` (~40); группы `group:u32` (~40); **параметры — из мест вызова**, перебор по графу вызовов до неподвижной точки (200–250); вместо четырёх запретов — проверки согласованности |
| Кодоген | 60–80 | `infer_type` знает типы параметров, полей, результатов вызовов — выбирает фиксированную арифметику |
| Сборщик мусора | 100–150 | сырое `u32` в поле Box или группе по младшим битам похоже на указатель; признак «сырой слот» в Box и заголовке группы, учёт в `rt_box_get/set`, обходах и барьере регионов |
| Канон и тесты | 80–100 | |

**Риски.** Самое рискованное — сборщик: ошибка там тихо портит память.
Ошибка типа всплывает далеко от причины (пометка автора) — смягчение:
сообщение называет, откуда пришёл тип («параметр `p` — `u32` из вызова в
строке N»).

**Поправка 04.11.2026:** автор решил, что канон станет RV64 в любом случае
([PLAN.md](PLAN.md), «Каноническая машина»). 3а нужен и при RV64; 3б (`u64/i64`
парой слов, 800–900 строк) — нет: на RV64 это одно слово.

## Bash-скрипты → Saltic — 04.11.2026

**Уточнение 04.11.2026 (вечер):** даже самым маленьким скриптам нужен
перехват вывода ребёнка. `bootstrap/stamp.sh` (21 строка) перезапускает
скрипт и читает его вывод построчно на лету, приписывая время `ЧЧ:ММ:СС`;
`workbench/hosts.sh` (30) запускает `nix … tests/run.sh` с переменной
`SALTIC_TEST_HOST`, пишет лог и фильтрует строки на лету. Прогноз, чтобы
переехали эти два, — **600–700 строк**: запуск процесса и код выхода
250–300; поиск по `PATH` 30–40; окружение (прочитать своё, задать ребёнку)
60–90; вывод ребёнка построчно через трубу, пока он работает, 130–160;
настенное время `ЧЧ:ММ:СС` с поясом (сейчас есть только такты) 40–60; тесты
и канон 60–80. Сами скрипты на Saltic — 80–100 строк вместо 51.
`tests/run.sh` (532) потребует ещё список файлов, сравнение вывода и замер
времени — следующий заход.


Подробно — в [PLAN.md](PLAN.md), «Инструменты». Коротко: 18 скриптов,
~1600 строк; платформе Linux не хватает запуска процесса, окружения и
списка файлов; запуск процесса — 250–300 строк. Отложено автором.
Решено 04.11: форма `process.run([…])`, поиск по `PATH`, вывод — `process.capture` и
`process.lines`. Открытый вопрос: [Q-010](QUESTIONS.md#q-010-переход-в-папку-для-запуска).
