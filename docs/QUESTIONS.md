# Открытые вопросы

Вопросы, которые ждут решения автора. У каждого — номер, суть, варианты,
рекомендация агента и ссылки: к какой фиче, разведке или пункту плана он
относится. Решённый вопрос уходит отсюда: решение записывается в
[PLAN.md](PLAN.md) рядом с фичей («Решение автора ДД.ММ.ГГГГ: …»), а номер
не переиспользуется. Разведки — в [RECON.md](RECON.md).

## Q-001. Откуда тип параметра

**К чему:** 64-битные числа, путь 3, шаг 3а —
[RECON.md](RECON.md#3а-фиксированные-типы-выходят-из-навыка--04112026);
[PLAN.md](PLAN.md), «Типы у параметров и результатов навыков» (решение
автора 03.11: чекер выводит типы сам, без подписей).

Чекер должен знать, что параметр `p` — `u32`, иначе выберет не ту арифметику.

- **Из мест вызова.** Тип параметра — тип того, что передают во всех
  вызовах; разные типы (то `u32`, то число) — ошибка. Требует обхода графа
  вызовов до неподвижной точки.
- **Из тела.** Тип — по тому, как параметр используют. Слабее: `out p` или
  передача дальше о типе ничего не говорят.

**Рекомендация:** из мест вызова, у параметра один тип; в ошибке — откуда
пришёл тип.

## Q-002. Литерал рядом с фиксированным

**К чему:** шаг 3а — [RECON.md](RECON.md#3а-фиксированные-типы-выходят-из-навыка--04112026);
переезд ОС с `hi/lo` на `u32`/`address`.

Писать `p + 24` вместо `p + u32.from(24)`: голый литерал берёт тип
фиксированного соседа. Новое правило языка. Без него в ОС после 3а будет много
`u32.from(…)`.

**Рекомендация:** принять — только для литерала, не для переменной.

**Автор 04.11.2026: думает.** Суть вопроса в разговоре: целое «внешне одно»,
но сорта различаются хранением и границей (обычное число — 29 бит с меткой,
`u32` — сырые 32 бита, `u8` — байт); `200 + 100` = 300, а
`u8.from(200) + u8.from(100)` — переполнение. Вектор мысли автора — в сторону
кратности байту (сорт по числу байтов, «или типа того»), пока не решено.

## Q-004. Равенство групп

**К чему:** [PLAN.md](PLAN.md), «Вектор качества», «Равенство групп по
ссылке»; тесты `tests/panels.saltic`, `tests/mrpc.saltic` — свой `same()`.

Сейчас `[1, 2] == [1, 2]` — `no`: сравниваются ссылки.

- по содержимому (как ждёт человек), рекурсивно;
- по ссылке, а для содержимого — навык `group.same(a, b)`.

**Рекомендация:** по содержимому — меньше сюрпризов; цена — `==` на больших
группах становится долгим.

## Q-008. Вид дробных чисел

**К чему:** [PLAN.md](PLAN.md), «Дробные числа» (решение 02.11: будут;
`~=` и `NEAR` решены 03.11); удобнее после 64-битных целых (Q-001, Q-002).

Плавающие (SSE на x86, F/D на RISC-V; `0.1 + 0.2` не ровно), десятичные
(точно, медленнее), рациональные (точно, без корней), posit (железа нет).
Грубо: плавающие на железе — 1 500–2 500 строк; десятичные или рациональные
программно — 800–1 200, но только поверх 64-битных целых.

**Рекомендация:** решать после 3б — от 64 бит зависит, что потянем.

## Q-009. UDP-транспорт в спецификации mRPC

**К чему:** mRPC агента — [os/target/uefi_x86_64/README.md](../os/target/uefi_x86_64/README.md),
«mRPC/1.0»; спецификация — github.com/zephyr-m/mRpc, `SPEC.md`.

Saltic говорит mRPC поверх UDP: одна датаграмма — один объект, `id` для
сопоставления, обрезка с `cut`, `help` страницами (`from`/`next`). В SPEC
такого транспорта нет.

**Рекомендация:** дописать в SPEC раздел «UDP» рядом с HTTP и WebSocket.
