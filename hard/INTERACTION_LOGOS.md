# Interaction Logos

Status: зафиксированное архитектурное направление после Logos v0.

## Главная идея

Счётчиковая машина и interaction nets не конкурируют и не заменяют друг друга.
Они описывают разные уровни одной системы:

```text
Logos v0 / Minsky counters  — минимальная физика сущности
Interaction nets            — универсальный протокол организации сущностей
```

Logos по-прежнему изменяет локальное состояние только простыми действиями
`NOP/INC/DEC/HALT`, принимает стикеры и выпускает стикеры. Interaction net задаёт,
какие Logos связаны, когда возникает активная пара и как взаимодействие перестраивает
сам граф вычисления.

## Представление графового агента

На первом этапе один агент interaction net является группой простых Logos:

```text
TYPE      тип агента
STATE     фаза локального протокола
PORT_0    главная связь
PORT_1    первая дополнительная связь
PORT_2    вторая дополнительная связь
LOCK      блокировка переписывания
PAYLOAD   данные агента
```

Каждое поле логически является счётчиком или группой счётчиков и изменяется через
единичные `INC/DEC`. Адреса в `PORT_*` образуют рёбра графа. Позже часто используемая
группа может быть физически уплотнена в один Logos с несколькими локальными
счётчиками, не меняя вычислительную модель.

## Редукция

Два агента становятся активной парой, когда соединены главными портами:

```text
A.PORT_0 ↔ B.PORT_0
```

Переписывание выполняется не новой аппаратной командой, а протоколом стикеров:

```text
DISCOVER  обнаружить активную пару
OFFER     предложить взаимодействие
LOCK      заблокировать обе стороны
MATCH     определить правило по TYPE
PREPARE   подготовить новые связи и свободные Logos
COMMIT    переключить PORT_0/1/2
RELEASE   освободить старые сущности и снять блокировки
```

Каждая фаза раскладывается на `INC`, `DEC`, проверку нуля и передачу стикеров.
Interaction rule является распределённой программой группы Logos, а не скрытым
опкодом физической клетки.

## Где находится вычисление

```text
состояния счётчиков  — состояние узлов
адреса портов        — структура графа
стикеры              — ход редукции
таблицы реакций      — локальный протокол
```

Программа и память существуют в одном изменяемом графе. Вычисление меняет не только
значения, но и состав сущностей и связи между ними. Независимые активные пары могут
редуцироваться параллельно.

## Инварианты направления

- Interaction nets не заменяют Logos v0.
- Графовая редукция не добавляет новые физические арифметические опкоды.
- Первый прототип обязан использовать группы существующих Logos и стикеры.
- Переписывание пары должно быть атомарным или восстанавливаемым после сбоя.
- Занятый или исчезнувший участник не должен приводить к молчаливой потере графа.
- Экран и человекочитаемый вывод не являются частью вычислительного ядра.
- Первая форма ввода и результата может быть двоичной трассой.

## Первый будущий эксперимент

Построить виртуальную ткань Logos v0, в которой две группы представляют два графовых
агента и выполняют одно полное переписывание исключительно стикерами:

```text
исходные TYPE и PORT
→ DISCOVER / LOCK / MATCH
→ изменение связей
→ COMMIT / RELEASE
→ новая корректная конфигурация графа
```

Трасса должна показывать каждый стикер, изменение каждого счётчика, старые и новые
связи, число тактов и восстановление после прерывания на любой фазе.

## Формула

```text
Logos задаёт минимальную физику.
Interaction net задаёт универсальную организацию.
Стикеры превращают взаимодействие в редукцию графа.
```
